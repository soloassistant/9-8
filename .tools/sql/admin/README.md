# 管理巡检 SQL 包（2026-10-31）

> 给**主理人**用：在 WorkBuddy 平台的「应用数据库」控制台（service role 连接）里逐个执行。
> 这些查询覆盖上市前没有管理后台的三张核心表：用户反馈、崩溃日志、订单对账。

## 纪律（先读）

1. **只读**。本目录所有语句只 SELECT；任何 UPDATE/DELETE 都必须先备份、并走
   `.tools/sql/v2-db-anon-revoke.sql` 同款的迁移留痕流程。
2. **PII 最小化**。`feedback.contact` 是用户联系方式，查询结果**不外传、不截图进仓库/群**。
3. 列名以代码插入路径为准（feedback: `type/content/contact/page` + 所有者与时间列；
   client_errors: `message/stack/page/channel/ua`）。首次执行若报列名错误，
   以控制台 `\d+ 表名` 的真实结构为准修正常量，并把修正**回提交进本目录**（口径单一事实源）。
4. 巡检节奏建议：**每周一次**反馈队列 + 错误趋势；**每次发版后 24h** 必看一次错误；
   订单对账在每笔支付问题工单时执行。

## 文件

| 文件 | 用途 | 频率 |
|---|---|---|
| `feedback-queue.sql` | 用户反馈队列（最新优先 + 未处理标记） | 每周 |
| `client-errors-daily.sql` | 崩溃按日聚合 + 最新 20 条明细（发版后看回归） | 发版后必看 |
| `orders-recon.sql` | 订单对账（按状态/渠道/金额汇总 + 近期明细） | 有支付工单时 |

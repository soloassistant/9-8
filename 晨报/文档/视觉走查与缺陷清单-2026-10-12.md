## 〇、先说我自己两次量错的地方

这份清单可信的前提是：**上一轮我给出的布局"问题"全是假阳性，根因在我的测量口径，不在 App。**
记在这里，避免下次再犯：

1. **开屏遮挡**：探针注释里写了「截图前点掉全屏层」，但代码里**只点掉了协议弹层**，漏了点开屏。
   结果 briefing / inbox / calendar / mine / library / shopping 这 **6 页截出来的整屏是橙色开屏页**，
   我据此得出的「气泡压住正文」「文字碰撞」等结论全部无效。
   （`src/components/Splash/index.tsx` 只有 `onClick`，**没有定时器**，不点就永远在。）

2. **用 `getBoundingClientRect()` 对行内元素做重叠判断 —— 方法本身不成立。**
   Taro H5 把 `<Text>` 编译成自定义元素 `<taro-text-core>`，构建产物里**没有任何 display 声明**，
   于是浏览器按 UA 默认渲染成 `display:inline`。行内元素的 `boundingRect` 是它**所有行盒的并集**，
   同一行上两个行内兄弟的 y 区间天然交错 → **恒定假阳性**。
   我最初报的「mine 近期动态标题碰撞」「learn 卡片文字碰撞」都是这么来的。

3. **修正后第一次又错**：我要求两个行内兄弟**横向重叠**才算命中，
   但同一行上的行内兄弟是横向**相邻**、不是重叠 → 正好把要找的情形过滤掉了（false negative）。
   最终口径：比较 `getClientRects()[0]`（第一个行盒）判断"是否同一行"，再用 computed 字号/字重区分
   "标题被并进正文"（真缺陷）与"行内正常排布"（不是缺陷）。

**一句话教训：验出不一致，先怀疑验的手段。**

## 二、确认缺陷 1：6 组「标题 + 正文」粘在同一行（系统性）

**根因**：这些 class 本意是块级标题，但 scss 里**漏写 `display:block`**，
而其父容器**不是 flex 容器**（只是 `flex:1` 的包裹层），所以标题与兄弟正文挤进同一行内流。
其中 `margin-bottom` / `margin-top` 对行内元素无效，**这本身就是"作者本意是块级"的强证据**。

| # | tsx 位置 | scss 位置 | class | 粘出来的实际效果 |
|---|---|---|---|---|
| 1 | `src/pages/mine/index.tsx:1012` / `:1022` | `mine/index.module.scss:482-487` / `:520-524` | `.logTitle` / `.logEmpty` | 「近期动态暂无动态。与 AI 对话、浏览热点、完成待办都会记录在这里。」 |
| 2 | `src/pages/learn/index.tsx:190` / `:191` | `learn/index.module.scss:323-327` / `:329-333` | `.recCourse` / `.recReason` | 「问候与自我介绍零基础从这里开口，先迈出第一步」 |
| 3 | `src/pages/briefing/index.tsx:1065` / `:1066` | `briefing/index.module.scss:415-420` / `:422-427` | `.eventTitle` / `.eventLocation` | 「{日程标题}📍 {地点}」 |
| 4 | `src/pages/inbox/index.tsx:629` / `:630` | `inbox/index.module.scss:503-507` / `:509-513` | `.historyText` / `.historyMeta` | 「{原文}入库 {n} 条 · {相对时间}」 |
| 5 | `src/pages/mine/index.tsx:818` / `:819` | `mine/index.module.scss:60-65` / `:67-70` | `.nickname` / `.userMeta` | 「p\*\*\*@example.test免费版用户」 |
| 6 | `src/pages/mine/index.tsx:836` / `:837` | `mine/index.module.scss:94-99` / `:101-106` | `.subTitle` / `.subDesc` | 「订阅私人晨报助理语音 20→不限次 · 收藏 50→」 |

**第 1、2、5、6 组已肉眼确认**（截图 `shots/mine-m.png`、`shots/learn-m.png` 可见粘连）；
第 3、4 组由代码结构 + 同文件对照证据判定（未在本次截图中触发，因为该数据为空）。

**"这是漏写、不是设计如此"的对照证据**（同一批文件里同类用途都写了 block）：
- `learn/index.module.scss:230-235` `.courseTheme` **有** `display:block`
- `calendar/index.module.scss:343-349` `.eventTitle`、`:351-356` `.eventLoc` **有** `display:block`
  （而 `briefing` 里**同名字段** `.eventTitle` / `.eventLocation` 却没有 —— 跨文件直接对照）

**修法**（二选一，一次性消除全部 6 组）：
- 给上述 12 个 class 统一补 `display:block`；**或**
- 把对应包裹层（`.logCard` / `.recBody` / `.eventBody` / `.historyBody` / `.userBody` / `.subCard`）
  改为 `display:flex; flex-direction:column`。

**明确排除的"设计如此"**（不算缺陷）：
`.levelName + .levelDesc`（等级名与描述故意同基线）、`.courseTitle + .doneBadge`（标题右挂徽章）、
`.price + .priceNote`（「¥6.9」与「/月 起」故意同行）。

## 四、确认缺陷 3：健壮性 —— 登录页依赖未固定版本的 CDN

- 当 `cdn.jsdelivr.net` 不可达时，登录页给用户看的是
  **「登录服务连不上（云服务未加载或网络不可达），请稍后重试」**（`language.ts:672` `auth.errSdkUnavailable`）。
  这是**代码里写好的正经兜底**，不是崩溃 —— 但用户看到的是技术措辞。
- 真正的问题是**依赖形态**：引用了**未固定版本的 `@dev` 构建**，且**没有 SRI 校验**。
  外部 CDN 被墙/被投毒/发新版本都会直接改变前端行为。
- 本次 20 张截图里 login 页就是这个状态（探针主动屏蔽 CDN 所致），属**受控复现**，非随机故障。

## 六、本次**未发现**问题的部分（也要如实说）

- 20/20 页面：`taroPages = 1`（无重定向期双页并存）、`readyState = complete`、`scrollW == innerW`（无页面级横向溢出）。

- 热点页内容充实（`textLen ≈ 21120`），非空白页。

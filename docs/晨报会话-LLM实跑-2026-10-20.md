## 三、抓到的两个真实问题

### 问题 1：推理阶段 ~20s 无任何 UI 反馈（体验）

`hy4-preview` 先输出 reasoning_content 约 20 秒才出 content。2s 截图：只有用户消息，无空气泡增长、无「正在思考」提示；30s 截图：完整回复。用户视角：**发出去后干等 20+ 秒，界面像卡死**。简单问题（问好）也走满推理。

### 问题 2：偶发静默挂死（第 3 次运行，75s 零回复）

同一探针同一操作：第 4 次 23s 成功，第 3 次 **75 秒硬顶仍零回复、零提示、llm_events 都没写**——说明 `cloudLlmChat` 的 SDK async 迭代器卡在 `await it.next()`（流不终止、无超时、catch 不触发）。`cloudLlmChat` 有 `opts.signal` 参数，但 `chatViaCloudLlm` 调用时**没传**——整条链无超时、无兜底、无错误日志。这正是项目明令禁止的静默失败。

## 四、误判纠正（如实记录）

- 第 2 次运行后我曾判「UI 无回复、缺陷坐实」——**下早了**：采样窗口只有 2.8s，而推理模型 ~20s 才出 content，窗口内无回复是正常的。
- 第 3 次运行 75s 硬顶 + 无 llm_events 请求，才真正证明挂死路径存在。
- 教训：**对带推理阶段的模型，「消息结构稳定」不等于「流程结束」**；终态必须等 sending 结束/足够长硬顶，且 UI 采样不能替代服务端信号（llm_events）交叉验证。

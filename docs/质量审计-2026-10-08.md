## 四、🟡 P1：静默失败（无提示、无日志、用户无感）

### 4.1 哑 `.catch()` 7 处

```
briefing/index.tsx:231  .catch(() => {})
briefing/index.tsx:614  .catch(() => {})
library/index.tsx:368   .catch(() => {})
library/index.tsx:394   .catch(() => {})
mine/index.tsx:255      .catch(() => {})
mine/index.tsx:266      .catch(() => {})
cloudSync.ts:129        .catch(() => null)
```

**这是本次审计里最值得改的一类。** 与「失败被 `console.warn` 吞掉」相比，连日志都没有 —— 出问题时**没有任何痕迹**可供排查。

其中 `cloudSync.ts:129` 返回 `null`，意味着跨设备同步静默失败而界面完全无感。

**建议**：至少给同步链路加 `console.warn`（不弹窗，避免打扰用户）。其余若确属「重定向失败可忽略」，建议加一行注释说明为什么可以吞。

### 4.2 空 `catch` 11 处（前端）

```
VoiceButton:497/502   data/legal.ts:35   library:187
cloud.ts:35/50        cloudSync.ts:53/136/225   tts.ts:450/488
```

多数是「读取 localStorage 失败就用默认值」这类合理兜底。**不建议一刀切加日志**（会在隐私模式等场景刷屏），建议只给 `cloudSync` 那三处加 —— 同步失败必须可见。

### 4.3 云函数 9 处

```

cloudfunctions/extract/index.js:47      空 catch
cloudfunctions/webSearch/index.js:474   空 catch
cloudfunctions/webSearch/index.js:631   空 catch
```

## 八、审计工具的已知局限（别把它当全量质量保证）

- 它是**静态扫描**，只认模式不认语义：同一个 `catch {}` 可能是合理兜底也可能是吞异常，它不区分（本报告已按 §四/§五人工分流）
- 它**没有跑起来** —— 运行时行为、类型层面的契约、端到端链路不在覆盖范围
- 它的中英文判定基于「语言表里是否已有相同 value」，所以**词条本身写错**它发现不了

> 结论一句话：**词条层是干净的（417/417 零缺口），漏在调用层**。这是个人工审查能补、静态扫描补不了的缺口。

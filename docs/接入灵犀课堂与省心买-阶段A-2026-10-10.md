## 2. 三个设计决策（都是"看起来该那么做、其实不该"的地方）

### 2.1 H5 用**相对路径** `/sxm/index.html`，不写绝对 URL

这是刻意的：**源码里绝不能出现本应用自己的沙箱域名**（`*.app.workbuddy.host` 会变、也可能被回收）。
写相对路径 ⇒ H5 端天然同源，且换域名时不需要改任何代码。
探针里专门断言了这一点 —— 点下去 `window.open` 收到的必须是 `/sxm/index.html` 这个**相对**串。

另外显式带上 `index.html`，不依赖静态服务的「目录索引」行为（`/sxm/` 会不会自动取 `index.html`
是服务端实现细节，不该赌）。

### 2.2 小程序端复制的是**各自耐久的那一套**地址

小程序里**无法内嵌网页**：本仓一个 `web-view` 页面都没有，而微信的 `web-view` 只对企业主体开放。
所以小程序端唯一能做的是把地址交给用户（复制 + 提示）。复制哪个地址就要挑了：

- **省心买 → 它的 GitHub Pages**（`https://soloassistant.github.io/shengxinmai/`）。
  上游 `index.html:8-19` 自己就把分享卡片钉在这一套上，理由写在它注释里：
  沙箱部署被回收的话，已经发出去的分享卡片会一起掉图。所以跟着它选耐久的那个。
- **灵犀课堂 → 它当前的 WorkBuddy 发布域**。它的旧自定义域
  `https://lingxi-class.app.workbuddy.host/` 已实测 **404**（多份文档仍写着它，口径过期），不要再用。

### 2.3 **没有**去"修正"省心买 `index.html` 里钉死的域名 —— 我一开始想错了

我最初的判断是：挂到 `/sxm/` 后，`og:url` / `og:image` / `twitter:image` / `canonical` 还指向
`soloassistant.github.io`，属于"要改成新域名"的 bug。

**读上游注释后确认是我错了**：社交平台爬虫不跑浏览器、没有 base URL 概念，`og:*` 必须是**绝对** URL
（相对路径在微信/Facebook/Twitter 全部失效），所以必须钉一个域名；而 GitHub Pages 是两套部署里
**耐久**的那套。把域名改成本应用的沙箱域，恰好会踩中它刻意避开的那个坑。

⇒ vendored 文件**保持原样，一个字节都不改**。这条已写进 `vendor/shengxinmai/PROVENANCE.md` 提醒后来者。

## 3. 验证（4 项，都可复现）

脚手架在 `.tmp-verify/sxm/`（临时验证目录，不进 `dist/`、不进版本控制）。

### 3.1 vendored 副本确实是上游当时那一版
13 个文件逐个 `sha256` 与上游本地仓库比对**全部一致**；且 `app.js` 的 sha1 前 12 位
`563fe0ae12e9` 在**上游本地与线上 Pages 两侧相同** ⇒ 这份副本就是当时线上跑的那一版。

### 3.2 构建期拷全、且没多拷
```
[copy-assets] sxm -> D:\Agent\dist\sxm: 13 files, 554351 B
[copy-assets] sxm 未纳入白名单（不会上线，符合预期）: PROVENANCE.md
```
反向断言：`PROVENANCE.md` **没有**进 `dist/sxm/`。这是"显式白名单"而不是整目录拷贝的原因 ——
`dist/` 是公开发布目录，多出来的任何文件都会被打包上线。

### 3.3 子页在真浏览器里真的能用（`probe-sxm.mjs`）
390×844 真 Chrome，注入云 SDK 桩后访问 `/sxm/index.html`：

| 检查 | 结果 |
|---|---|
| 渲染出来（标题 + 正文） | ✅ 标题「省心买 · AI 比价与出行助手」，正文 1643 字 |
| 自身 7 个资源请求 | ✅ 全部 200，**0 个 >=400** |
| 根路径 `/api/health` | 404 —— **按设计降级**为「手动比价」 |
| 未捕获异常 / 加载失败 | 0 / 0 |

> `/api/health` 404 是**预期**而不是缺陷：省心买前端探测不到后端就置 `SERVER_OK=false` 自动降级，
> 这与它自己挂在 GitHub Pages 上的行为**完全一致**（Pages 也没有后端）。所以 `dist/sxm/`
> 不是"带后端的省心买"；要真比价得另外部署它的零依赖 Node 后端并配联盟密钥。

### 3.4 入口**点下去**真的开对地址（`probe-partner.mjs`）
只断言 DOM 里有卡片是假验证（"渲染了"和"点了有用"是两件事）。所以注入 `window.open` 记录器，
再用**真实鼠标**点卡片中心：

| 路径 | 观测到的 `window.open` | 结论 |
|---|---|---|
| 购物页 → 省心买 | `["/sxm/index.html"]` | ✅ 相对路径（没被写成绝对 URL） |
| 学习页 → 灵犀课堂 | `["https://bb6ae4d03fbd4b109cbbe6dbbc84502d.app.workbuddy.host/"]` | ✅ |

另断言：H5 端按钮文案是「浏览器打开」，且**不出现**小程序端的「复制链接」。

## 5. 阶段 B（小程序原生重写）的计划与阻塞点

阶段 B 不是"把网页塞进小程序"，而是**在小程序里重做这两个产品**。分两期，按风险从低到高：

### 5.1 第一期：省心买（风险低，可以马上做）
现有 `pages/shopping` 已经有清单/手动记价/降价提醒。B 要补的是省心买的这几块：
- **静态字典入口**：`vendor/shengxinmai/data.js` 里的 `SHOP_PLATFORMS` / `FOOD_PLATFORMS` /
  `FLIGHT_PLATFORMS` / `RAIL_OFFICIAL`（平台入口 URL 模板）与 `CITY_AIR` / `CITY_GEO`（城市三字码与坐标）
  —— 这些是**纯静态数据、不含价格**，可以直接搬到 `src/data/` 下做成小程序可用的结构。
- **手动比价 UX**：把各平台搜索页摆好、一键复制/跳转；**不显示任何价格**（无密钥时不编造价格）。
- **机票/火车票查询入口**：同样只做跳转，不做查询（真查询要 ignav 密钥 + 服务端）。
- ⚠️ **不能做**的：真·比价数据要联盟密钥且**密钥必须留在服务端**（省心买 README:145
  「任何 APP_SECRET 都不能进前端」）。小程序里放密钥＝泄露，这条路直接排除。

### 5.2 第二期：灵犀课堂（阻塞点多，需要你先给两个东西）
上游已交付完整《灵犀课堂小程序-联动开发规格书》（45 KB 规格 + 30 KB 接口契约与参考实现），
小程序作为**第二个客户端直连同一朵云**（同账号同数据，不是数据同步）。但落地前卡在两件事上：

1. **一个真实的小程序 AppID**。当前 `project.config.json` 还是 `touristappid`，
   而运行时需要在微信后台把 `https://mp-api.app.workbuddy.host` 配成
   **request 合法域名** —— 不配，真机一个请求都发不出去。
2. **登录必须用「手机号 + 验证码」**。规格书实测：微信一键登录走不通
   （`POST /.cloud/auth/v1/login-wechat` 返回 `access_denied`，因为网页版属 Web 类型应用），
   用微信登录会得到**另一个身份**、读不到网页版的数据。

另外上游有两处技术债会直接影响 B：`courses` / `student_profiles` / `student_facts` /
`student_sessions` / `analytics_events` 五张业务表的 **DDL 与 RLS 不在版本控制里**；
`analytics_events` 的 RLS 在未登录时被判为 `'anon'` 而非 NULL，**数据库层允许未登录读写**。

### 5.3 结论
阶段 B 我可以先做 **5.1（省心买原生页）**，它不需要任何密钥；**5.2（灵犀课堂原生页）** 需要你先给
小程序 AppID 与后台域名配置，否则只能做"能编译但连不上云"的骨架 —— 那种东西我不建议交付，
因为它看起来能用、实际登不上。

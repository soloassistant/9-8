# 题库 OCR 可行性 spike（gaokao.com 扫描真题）

> 实测日期：2026-11-05　范围：设备 OCR 能力盘点 + 扫描图 OCR 抽样 + 人工核对
> 结论只覆盖「扫描图 → 纯文本 OCR → 结构化题干」这条链路，不覆盖公式 OCR、PDF 文本层等其他路径。

## 结论先行

1. **设备上唯一可直接用的是 Windows 自带 OCR**（`zh-Hans-CN`，`MaxImageDimension=10000`），12 张图全部识别成功。
2. **本地 Python 没有任何 OCR 能力**：Python 3.15.0，`pip list` 只有 `pip`；`pytesseract`/`paddleocr`/`easyocr`/`rapidocr_onnxruntime` 均未安装，Tesseract 二进制也未安装。
3. **微信云函数侧没有 OCR 调用，也没有 OCR 依赖**：`cloudfunctions/` 全目录 grep `ocr` 无命中；依赖只有 `wx-server-sdk`（少量函数加 `alipay-sdk`）。平台是否提供 OCR openapi **未测到**。
4. **抽样 20 页只得到 12 张唯一图**（源站同图复用），**20 张唯一扫描图：未测到**；下表按 12 张唯一图报实测。
5. **纯文本 OCR 对数学题不可用**：5 张人工核对中，题干/选项的数学符号共 79 处，OCR 正确保留 **0 处，错误率 100%**；连「试卷/答题卡/填涂」都被识别成「吾巷/吾卡/埴涂」。
6. **三段切分不可靠**：12 页里选项行命中 **0/12 页**，答案标记命中 **0/12 页**；题号行仅 11 行且多为误检。
7. **判断：当前路径不值得做**。只有满足「原始 PDF 或 ≥150 DPI + 公式 OCR + 校对 ≤60 秒/题 + 许可解决」才转为「有条件值得」。

## 5. 数学符号识别错误率

统计口径：上述 5 张人工核对图，范围仅「题干 + 选项」，不含解析；人工逐项计数四类符号实例，再逐项判断 OCR 输出是否保留。允许 ±2 的边界口径差异（如度数符号是否计入上标）。

| 符号类别 | 实例数 | OCR 正确保留 | 错误率 |
|---|---|---|---|
| 分数（含 `1/(z−1)`、`√5/10`、`60/5`、`½x²` 等） | 22 | 0 | **100%** |
| 根号（`√3`、`√6`、`√5/10`、`√6/2`、`√7` 等） | 11 | 0 | **100%** |
| 上标/下标（`x²`、`a²`、`eˣ`、`x³`、`S₅`、`a₅`、`x₁`、`Pₙ` 等） | 36 | 0 | **100%** |
| 希腊字母（`α`、`π`、`φ`、`θ` 等） | 10 | 0 | **100%** |
| **合计** | **79** | **0** | **100%** |

字符级复核（12 页全量 OCR 文本）：`√ ² ³ π α β γ θ φ ∠ △ ∩ ⊥ ≥ ≤ ≠ ∈ ∁` 的出现次数 **12/12 页均为 0**。

上采样试验（sample-02）：

| 倍率 | 字符数 | OCR 耗时 | 符号保留 |
|---|---|---|---|
| 1×（563×781） | 685 | 361 ms | 0 |
| 2×（1126×1562） | 941 | 214 ms | 0 |
| 3×（1689×2343） | 965 | 227 ms | 0 |

上采样让汉字与行结构略好（字符数 +37%），但**数学符号仍然 0 保留**——瓶颈不是像素尺寸，而是引擎不具备数学结构识别能力。

> 未计算严格 CER（字符错误率）：需要逐字对齐标注，本次未做。上述 79 处为逐项人工判定，正确数为 0 是确定值，不受口径差异影响。

| **合计** | **11** | **0** | **0** |

判断：**不可靠**。

- 选项行 0/12：OCR 把整行四个选项合并或打散，例如 sample-01 第 1 题选项被并成 `12 俨 D 13`，没有稳定的 `A./B./C./D.` 行首。
- 答案标记 0/12：`【答案】`、`【解析】` 全部识别失败。
- 题号行 11 行里多数是「注意事项 1./2./3.」这类说明文字，不是题干起点；sample-01 的 3 行分别对应注意事项，而非 6 道题。
- 失分根源是版面结构（多栏、公式块、行内上下标）在纯文本化后消失；靠正则补不回来，需要坐标级版面分析。

## 7. 四条判断

### 7.1 纯文本 OCR 对数学题够不够用？

**不够用。** 依据是实测而非印象：

- 数学符号 79 处，正确 0 处，错误率 **100%**。
- 5 张人工核对图，**5/5** 无法得到可用的题干；错误发生在题干关键位置（分数线、根号、上标、集合/区间、向量）。
- 即使只看汉字正文，也存在高频形近字替换（试卷→吾巷、答题卡→吾卡），必须人工逐字校对。
- 三段切分 0/12 页命中选项与答案标记，无法自动结构化。

### 7.2 若要提高到可用水平，需要什么？

1. **更高分辨率的输入**：当前 544–571 px 宽，按 A4 折算约 66–69 DPI，远低于 OCR 常用的 150–300 DPI。需要原始 PDF 或出版社级扫描件。
2. **公式 OCR，而不是纯文本 OCR**：需要输出 LaTeX/MathML 的模型（Mathpix、Pix2Text、LaTeX-OCR、PP-FormulaNet 类），并单独测公式准确率（本次**未测到**）。
3. **版面分析**：按坐标恢复「题干区 / 选项区 / 答案区 / 解析区」，不能只靠文本正则。
4. **人工校对环节**：至少对公式与关键数字逐题复核。

### 7.3 人工校对成本估算（估算，非实测）

> 说明：本次只计了机器 OCR 耗时（median 355 ms/页），**没有对人工校对计时**；下面是按工序拆分的估算，不冒充实测。

| 场景 | 单题工序 | 单题耗时 | 1000 题工时 |
|---|---|---|---|
| A. 纯文本 OCR 不可用，按原图重录题干+选项+答案 | 读图、录题干、录选项、录答案/解析、复核 | **180–300 秒** | **50–83 工时** |
| B. 只重录题干与选项（答案另找） | 读图、录题干、录选项、复核 | **约 120 秒** | **约 33 工时** |
| C. 公式 OCR 可用，人工只校符号与数字（目标门槛） | 对照公式输出、改错、抽检 | **≤60 秒** | **≤17 工时** |

参考：机器侧成本很低——单页 419.6 ms（均值），一份 4 页试卷约 **1.7 秒**；瓶颈完全在人工。

### 7.4 值不值得做？

**当前路径：不值得。** 条件：纯文本 Windows OCR + 545–571 px 扫描图 + 无人工预算。

理由：

- 符号错误率 100%，等价于「OCR 只帮忙认了汉字，公式仍要人重录」；
- 按场景 A 估算，1000 题需 50–83 工时，产出还不如直接找有文本层的源；
- gaokao.com 页面版权标注为「All Rights Reserved」（见上一份《题库-源产出勘察》），许可本身也未解决。

**有条件值得**，需同时满足：

1. 拿到**原始 PDF 或 ≥150 DPI** 扫描件（当前图源不满足）；
2. 接入**公式 OCR**（LaTeX 输出），且公式准确率达到可校对水平（需单独 spike，本次未测到）；
3. 人工校对压到 **≤60 秒/题**（对应 1000 题 ≤17 工时）；
4. **许可问题解决**：获得明确转载/改编授权，或换到明确许可的源；
5. 有版面分析能力，能稳定切出题干/选项/答案三段（当前 0/12 页）。

四条里缺任何一条，都会退回「不值得」。

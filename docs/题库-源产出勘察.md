## 结论先行

1. **没有任何候选源能在「明确许可」前提下单独喂饱 MVP。** 唯一同时满足「robots 允许 + 明确 CC 许可 + 实测有题」的是 `zh.wikibooks.org`，但 20 次请求只产出 81 题，其中 66 题是「31+5=」这类裸算式。
2. **产出侧唯一像真题的是 `gaokao.com`**，但 20/20 页的题目全部是扫描图，可解析文本题 **0 道**；页脚是「版权所有 … All Rights Reserved」。要拿产出必须下载图片做 OCR（不能落盘、不能代理，否则触硬线 1）。
3. **`zxxk.com` 在第 1 页就返回 JS 挑战页**，robots.txt 本身也是挑战页，按 fail-closed 整站跳过，不做绕过。
4. 两个同许可的 Wikimedia 兄弟站：`zh.wikiversity.org` 20 页只有 7 题；`zh.wikisource.org` 20 页 0 题（是古籍/数学史，不是题库）。
5. 因此：**合规首选 wikibooks，但它是「能跑通链路」的量级，不是「能喂饱」的量级。**

## 结论：谁能喂饱 MVP

**合规前提下，没有单源能喂饱。**

- `zh.wikibooks.org` 是唯一「许可 + robots + 可解析」三者都成立的源。实测产出 81 题 / 20 次请求，结构是：3 个 `<ol>` 练习页共 71 题（其中 66 题是裸算式，5 题是应用题）；其余 10 题来自 quiz（3）、编号长题页（6）与孤立选项（1）。真正可独立作答的完整题干 14 题（17.3%）。这足以证明「抓→解析→入库→展示」链路，但不足以支撑一个看起来像题库的产品。
- `zh.wikiversity.org` 是「同许可 + 有题」的补充源，但密度 0.35 题/页，不能当主源。
- `zh.wikisource.org` 许可清晰、抓取稳定，但 0 题，不能当题库源。

**如果坚持要高产出，必须接受的具体合规风险：**

1. **`gaokao.com`：** 产出全在扫描图里。要拿题必须把图片下载到内存做 OCR（一旦落盘或代理图片就触硬线 1）；同时页脚是「版权所有 … All Rights Reserved」、正文写「来源：网络整理」。这不是「无明确许可」的灰区，而是**版权方明确保留权利**。可接受的做法只有：不存原图、不代理图片、OCR 后即弃、来源标注 + 48 小时下架通道，并且接受「随时被要求下架、无法主张许可」的风险。
2. **`zxxk.com`：** 站点用 JS 挑战主动拒绝自动化访问。绕过挑战在技术上可做，但属于规避站点技术措施，且站点是商业付费平台；这条不做，不是「暂时不做」。
3. **`zh.wikibooks.org`：** 风险不是「能不能抓」，而是 **CC BY-SA 4.0 的传染性**。用户看到的每道题都要署名 + 链到许可 + 标明是否修改；若题目被混合进自建题集，衍生部分需同许可共享。这是持续义务，不是一次性声明。

## 如果只能选一个源

**我选 `zh.wikibooks.org`。**

- **理由（Y）：** 它是唯一一个三项同时实测通过的源——robots 明确允许 `/wiki/` 内容页；页面 `<link rel="license">` 与页脚都指向 CC BY-SA 4.0；20 页实测确实能抽出题（81 题，6/17 唯一页有题），且解析不需要 OCR、不需要登录、不需要绕挑战。用它可以在合规边界内把 MVP 全链路跑通。
- **代价（Z）：**
  1. **量不够且分布畸形**：4.05 题/请求，66/81 是「31+5=」这类裸算式；完整题干只有 14/81。要凑出一个可用的题集，页面筛选成本会远高于题目本身的价值（具体需要多少页未测，不估）。
  2. **答案几乎为零**：有题目页 0/6 带答案；唯一真正的答案区（第 17 页）没有可配对的题目。答案要么自己生成并明确标注「AI 生成，待校正」，要么产品接受「只练不判」。
  3. **内容不是真题卷**：是教材正文/课后练习，难度与题型结构都不等于考试卷；「高考真题」这个卖点用它撑不起来。
  4. **CC BY-SA 义务长期存在**：每题展示需署名、许可链接、修改标注；衍生题集需同许可共享。这条会进入 UI 与用户协议，不是代码层能消化的。
  5. **维护成本**：练习页结构三种（quiz / `<ol>` / 编号长题），且存在繁简重复页与「提名删除」页，解析器必须按页型分流并持续校准。

## 许可判断方法（怎么判「明确标注可转载/CC」）

1. **看页面里的机器可读声明**：Wikimedia 系页面 `<head>` 有 `<link rel="license" href="https://creativecommons.org/licenses/by-sa/4.0/deed.zh">`；页脚另有「本网站文字内容采用…知识共享署名-相同方式共享许可协议授权」并链到 `creativecommons.org/licenses/by-sa/4.0/deed.zh-hans`。三站（wikibooks / wikiversity / wikisource）均实测命中，判定为**明确许可 CC BY-SA 4.0**。
2. **看页脚版权句的反面**：`gaokao.com` 页脚为「高考网版权所有 Copyright 2005-2022 www.gaokao.com . All Rights Reserved」，正文来源标「网络整理」——没有任何转载许可，判定为**无明确许可（保留所有权利）**，不按「可转载」处理。
3. **看 robots 是否可信**：`zxxk.com`、`basic.smartedu.cn`、`zh.khanacademy.org`、`www.pep.com.cn` 返回的是 HTML 挑战/普通网页而非纯文本 robots。按「无有效规则即整站跳过」处理，**不进入许可判断**，也不尝试解密挑战。
4. **只认「站点自己说的」**：不把「网上到处都能搜到」当许可，也不把「robots 允许」当转载许可——robots 只说明「允许抓」，不说明「允许再发布」。

## 方法与合规记录

- **时间**：2026-11-05，单机串行。
- **UA**：`MorningBriefBot/1.0 (research; contact: ops@example.com)`。
- **限速**：每个请求之间固定 1200 ms（`GAP=1200`），单线程 `for` 循环，无并发、无重试轰炸；单请求超时 15 s；最多 3 次重定向。
- **robots**：先抓各站 `robots.txt`；只对「纯文本 robots 且路径未被 Disallow」的 URL 发请求。`zxxk` / `khanacademy` / `pep` / `smartedu` 因 robots 无效整站跳过；`gaokao` 只抽 `/e/` 文章页，未触碰 `/高考/`、`/test/`、`/website/`。
- **编码**：按 `content-type` 或 `<meta charset>` 嗅探；`gaokao` 为 GB2312，已用 `TextDecoder('gbk')` 解码。
- **不存正文**：仓库内没有保存任何题目原文或页面 HTML；本文件只保留 ≤30 字样例与来源 URL。原始 JSON 在 `%TEMP%/qbprobe`，属临时文件，未提交。
- **解析口径**：
  - Wikimedia：取 `mw-parser-output` 到 `printfooter` 之间的主内容。
  - quiz：按 `<div class="question">` 切块，`class="proposal"` 计选项，`class="answer"|正确答案|【答案】|参考答案` 判定有答案。
  - `<ol>`：首个 ≥5 项、且 ≥60% 项含 `= / ？ / ○ / 求 / 计算 / 化简 / 解方程` 的列表计为题目；`○|____|（ ）|(=|＝)$` 计填空。
  - 文本题：编号行 + 问句信号；排除教材目录（`^\d+\.\d+`）与出版信息/参考文献行。选项组要求前 4 行内存在长度 ≥8 的非选项题干，避免把孤立选项误计为一道题。
  - 答案判定统一收紧为 `【答案】|参考答案|正确答案|答案：`，避免把教材正文里的「解析几何」误判成答案。
- **抽样清单来源**：wikibooks 取「高中数学 / 初中数学 / 小学数学 / 大学数学 / 中学数学」及 `Category:初中数学` 等分类里的内容页；wikiversity / wikisource 取数学分类条目；gaokao 取 2025 年各省数学「试题 / 试题答案」文章页；均为内容页，未把首页计入样本。
- **偏差与限制**：
  - wikibooks 20 次请求只覆盖 17 个唯一页（3 组编码/繁简别名重复），所以同时给出「20 次请求」和「17 唯一页」两个口径。
  - 解析器是启发式，不是人工逐题核对；「题干完整」按长度/问句信号判定，裸算式被算作可抽取题干，因此 98.8% 与 17.3% 两个口径同时列出，后者更接近产品可用性。
  - 未做 OCR，`gaokao.com` 的图片题量、题型、答案占比一律「未测到」。
  - 未做全站枚举，任何「总题量」结论都不成立。

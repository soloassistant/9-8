### C2 做了什么（`src/index.html`）

```html
<script defer src="https://cdn.jsdelivr.net/npm/@tencent-ai/workbuddy-cloud-sdk@0.1.3-dev.c090db7.202610050023/lib/index.global.js" integrity="sha384-fjris8pRF0OENf5gUBh3VN3hCPgW92IW8Uunpc12O8bnah0T8rCp6TF7JGdFIyr0" crossorigin="anonymous"></script>
```

- **① 固定版本**：钉到 `dev` 当时解析到的**那个具体版本**（不是 `latest`）。
  `index.html` 原有注释写着「不要改成固定版本号」，理由是「`latest` 尚未维护、指向旧构建」——
  这条**没有被违反**：固定的是 dev 线构建，`latest`(0.1.3) 依然没被使用。
- **② 固定不改变字节**（关键证据，两次下载分别取自两个 URL）：

  | 下载对象 | 字节数 | sha256 |
  |---|---|---|
  | `@dev/lib/index.global.js` | 67666 | `0e1ab581383d9103f58e5776badec1ce48de1d2977bf6772e142c3b2e4e400a3` |
  | `@0.1.3-dev.c090db7.202610050023/lib/index.global.js` | 67666 | 同上（`cmp` 报 **BYTES IDENTICAL**） |

  ⇒ 固定版本**没有**改变当前加载的内容，只是把"以后 CDN 发新版会静默改变登录行为"这条风险摘掉。
- **③ SRI**：`sha384-` + base64(sha384(该文件字节))。两处独立算法互证：
  `openssl dgst -sha384 -binary | openssl base64 -A` 与 Node `crypto.createHash('sha384')`
  得到同一串 `fjris8pRF0OENf5gUBh3VN3hCPgW92IW8Uunpc12O8bnah0T8rCp6TF7JGdFIyr0`；
  连浏览器自己算出来的也是它（见 C3 的 bad-sri 报错原文）。
- **④ `crossorigin="anonymous"`**：jsdelivr 回 `access-control-allow-origin: *`（已 `curl -I` 核对），SRI 跨域校验可用。
- 构建产物核对：`dist/index.html` 里三属性**完整保留**（html-webpack-plugin 没有吞掉）：

  ```
  <script defer="defer" src="https://cdn.jsdelivr.net/npm/@tencent-ai/workbuddy-cloud-sdk@0.1.3-dev.c090db7.202610050023/lib/index.global.js" integrity="sha384-fjris8pRF…" crossorigin="anonymous">
  ```

> `defer` 是上一轮已做的（SDK 慢/不可达时不再阻塞首屏），本轮保留。

### C4 顺带挖出并修掉的真缺陷：SDK 缺失时登录回「账号或密码不正确」

这不是任务点名要查的，是 C3 的 `block` 场景顺出来的。**先复现、后修**：

复现（`bash .tmp-verify/cdn-sri/run-login-error.sh`，屏蔽 CDN 后**真的填表 + 勾选 + 点登录**）：

```
提交后: errorText = "账号或密码不正确"      ← 改之前
交互自检: {"emailTyped":true,"pwdTyped":true,"privacyOn":true}
```

链路：`cloudAuth.safeAuth` 在 SDK 取不到时返回 `error.kind='backend-unavailable'`，
但 `submitPassword` 把这个 error 一律映射成 `auth.errWrongCredentials`。
⇒ 用户填的是**完全正确**的邮箱密码，却被告知"账号或密码不正确"，于是去重置密码（重置同样会失败），
把「依赖挂了」误判成「自己记错了」。**这是不实告知**，且恰好违反登录页自己那句注释
「连不上就别让用户对着一个必然失败的表单空点」。

修法（一处收口，`src/pages/login/index.tsx`）：新增模块级 `sdkDownText(error, t)`，
凡 `error.kind === 'backend-unavailable'` 一律给出 `auth.errSdkUnavailable`；
**5 个**提交分支（发码 / 密码登录 / 验证码提交 / 发重置邮件 / 提交新密码）全部走它。
刻意**不**把 `error.message` 透出去 —— 密码登录有意不区分"账号不存在/密码错"，透传 SDK 原文会破坏这个反枚举口径。

修复后同一探针带断言复跑：

```
实测错误文案: "登录服务连不上（云服务未加载或网络不可达），请稍后重试"
PASS  期望 "登录服务连不上（云服务未加载或网络不可达），请稍后重试" / 实际 同上
```

> 表单**仍然渲染**（代码只加提示、不禁用表单，用户可能稍后重试时不想丢输入）——
> 这是既有设计，本轮**不改**；只把「提交后给出的结论」修成真话。

### C5 selfcheck 假红：是我改了 CDN 才暴露出来的**判据过时**

改完 C2 后，`npm run selfcheck` 立刻 **FAIL 1 项**：

```
[FAIL] 进入门禁在位（未登录不得进入 + 无假身份兜底）—— … noFake=true sdk=false
```

根因（`.tools/selfcheck.js:441`）：`const sdkLoaded = /workbuddy-cloud-sdk@dev/.test(html)` ——
**判据把渠道写法写死了**。我把渠道从浮动的 `@dev` 收紧成固定版本，这个正则就不匹配了
⇒ 把"渠道收紧"误报成"SDK 没了"。**是判据错了，不是修复丢了**（与上一轮 D1 那两条同类）。

改法：判据改成按**形状**判定，并顺手把它升级成漂移守卫 ——
① 有 SDK `<script>`；② 渠道是 dev 线（`@dev/` 或 `@x.y.z-dev.xxx/`）；③ **带 integrity + crossorigin**。

**变异对照（证明新判据不是恒真）**：

## 一、我们有什么（诚实的能力基线）

**已具备且是差异化的资产**
- 每天一份「私人晨报」：自适应开场（F21 busyDay 排序）+ 日程/待办 + 天气 + 按偏好排序的 RSS 情报（F22 兴趣筛选）+ 语音播报（F20 TTS 分块队列）。
- 收件箱三通道输入（粘贴/截图/语音）→ AI 提取事件/待办/收藏 → 冲突检测。
- 「**先提议后执行**」的人机边界契约（plan / proposals / applyPlan），代码级存在。
- 微信转发/截图提取作为唯一合规入口（大厂 IM 绑定自家、读不了微信聊天，这是护城河）。
- 购物清单 + AI 比价意图、学习模块（多语种课程 + 闪卡 + 成就 + 本机社区打卡）、历史晨报归档、记忆管理仪表盘、6 色主题/中英字号。
- 降级链完善（断网/无服务端走 mock，不白屏）。

**一句话**：我们在「微信生态内的晨报仪式感 + 先提议后执行的信任边界」上是窄而深的，但在**情报质量、规划深度、支付闭环、合规资质、多端一致**上普遍落后于上市竞品。

## 三、不足清单（共 27 条，均锚定真实代码）

> 列格式：不足点 ｜ 对比竞品 ｜ 差距等级（高/中/低）｜ 代码状态 ｜ 建议方向

### A. 情报/资讯聚合（最薄弱区，5 条）

**A-1 今日情报无原文链接、不可点开溯源**
- 对比：今日头条 / 知乎日报（每条可点原文）
- 等级：**高**（日报类留存头号杀手）
- 代码状态：缺失 —— `src/types/index.ts:56` `intelItems: Array<{ text; source }>` **无 `url` 字段**；评估文档 `intelItems-url-溯源评估-2026-10-08.md` 说明改动牵连 H5/小程序双端契约（被冻结）。
- 建议：解冻 `types` 加 `url`，情报卡可点源；先不追求双向契约，仅展示原文链接。

**A-2 跨源同事件去重缺失**
- 对比：今日头条 / 微博热点（跨源折叠同一事件）
- 等级：**高**
- 代码状态：缺失 —— 全仓无 `simhash`/标题归一化；`webSearch/index.js:1128-1129` 把「同类目硬去重」放在前端，**那是类目配额不是跨源同事件去重**。
- 建议：`webSearch` 出口加 SimHash/标题归一化折叠；纯 CPU、零 token，不烧月度配额。

**A-3 资讯源窄且偏 RSS，缺社媒/短视频/公众号深度流**
- 对比：今日头条（多源+算法）、微信「看一看/听一听」
- 等级：**中**
- 代码状态：缺失（受资质限制）—— `webSearch` 仅 12 个 RSS + 通义 `enable_search`；无社交/短视频/公众号源。
- 建议：扩源 + 接入更多合规信源；时政/突发类需《互联网新闻信息服务许可证》（见 I 类）。

**A-4 个性化推荐弱，仅规则兴趣筛选，无强算法**
- 对比：今日头条（强推荐算法 + 可解释）
- 等级：**中**
- 代码状态：有但弱 —— 仅有 `F22` AI 兴趣筛选（规则/mock 兜底），无协同过滤/向量召回。
- 建议：在兴趣筛选之上叠加重排 + 「为什么推这条」的可解释标签；保留设置级关闭入口（已具备 `appPrefs.aiFilterEnabled`）。

**A-5 已读/不感兴趣状态机缺失**
- 对比：今日头条 / 豆瓣（「不感兴趣」+ 已读不再推）
- 等级：**中**
- 代码状态：缺失 —— `grep isRead/markAsRead/readAt` 全空；只有连读天数 `readStreak`。
- 建议：加已读状态机，已读/点「不感兴趣」后不再推送同条。

### B. 日程 / 待办 / 规划（4 条）

**B-1 冲突后无一键重排方案**
- 对比：Motion / Reclaim.ai（自动重排，需用户批准）
- 等级：**高**
- 代码状态：缺失（管线闲置）—— `extract` 只检测不解决；`plan/applyPlan` 提案制契约已存在（`L1842-1845`）却未接冲突场景。
- 建议：晨报/日历检测到冲突 → 「让 AI 重排」按钮 → `action='plan'` 出 proposals → 用户勾选 → `applyPlan` 落库（全复用既有逻辑，不新增写库）。

**B-2 晨报无工作量负载可视化**
- 对比：Sunsama（今日已排 Xh / 可用 Yh 负载条）
- 等级：**中**
- 代码状态：缺失 —— 晨报只罗列清单，用户看不出「今天排爆了没有」。
- 建议：晨报顶部加 `今日已排 X.Xh · 空闲 Y.Yh`，超阈值（如 >70% 醒着时长）提示「今天偏满，保 3 件事」。

**B-3 无周复盘 / 周报**
- 对比：Sunsama weekly review / 滴答周视图
- 等级：**中**
- 代码状态：缺失 —— 仅有「历史」归档，无聚合统计。
- 建议：每周日晨报附一屏：本周完成/超时/被挪项统计 + 下周重头事（数据来自 `events/todos` 聚合，无新依赖）。

**B-4 待办与日历未深度绑定（无时间块/番茄钟）**
- 对比：滴答清单（番茄钟 + 时间块拖入）
- 等级：**中**
- 代码状态：缺失 —— 待办与日程两套列表，无时间块绑定、无番茄钟。
- 建议：待办可拖入日历时间块；加番茄钟计时（复用本地状态）。

**B-5 系统日历无法导入**
- 对比：通义 / 飞书（读多端日历）
- 等级：**中**（护城河属性兼具）
- 代码状态：缺失（且平台限制）—— `grep addPhoneCalendar` 全空；小程序无「读系统日历」API，仅能单向写入。
- 建议：降级为「单向写入系统日历 + ICS 导入」，**不立项双向同步**（平台不支持）。

### C. 习惯守护（2 条）

**C-1 习惯守护「先斩后奏」披露不足**
- 对比：Reclaim（习惯保护 + 透明）
- 等级：**中**
- 代码状态：有但弱（且与核心纪律张力）—— `HabitGuardBar` 自动挪（`autoMoved`，`L10927`），仅事后守卫条撤销；与「先提议后执行」纪律冲突，且晨报首屏不显著展示。
- 建议：保留自动挪的好体验，但把披露前置——当日有被挪项时晨报首屏显著列出「AI 为保护习惯挪了这几件事 + 原因 + 撤销」。

**C-2 习惯维度窄（仅时段保护，无多维打卡/趋势）**
- 对比：小睡眠 / 微习惯（多维习惯 + 连续打卡 + 趋势图）
- 等级：**中**
- 代码状态：缺失 —— 仅时段保护，无打卡计数、连续天数、趋势可视化。
- 建议：丰富习惯维度（频率/计数/连续天数）+ 趋势图 + 成就激励。

### D. 对话 / AI 能力（3 条）

**D-1 chat 内无真·联网搜索工具**
- 对比：豆包 / 通义 / ChatGPT（任务模式真工具调用）
- 等级：**高**（Agent 定位最硬短板）
- 代码状态：有 webSearch 但 chat 未调用 = 能力缺口 —— `chat` LLM 自认「无搜索工具」（`项目源码整合.md L1836`）；`webSearch` 云函数存在却未被 chat 路由复用。
- 建议：`chat` 识别查价/查资讯意图 → 复用 `webSearch` 的 RSS 源 + 天气接口 → 注入上下文再生成；断网/源失效明确标注「未能联网」，绝不装作查过。

**D-2 语音播报无打断 / 连续对话弱**
- 对比：豆包 / 智能音箱（可打断、自然停顿）
- 等级：**中**
- 代码状态：有但弱 —— `tts.ts` 分块队列播报，无打断（TTS 打断在 P2 路线图）。
- 建议：TTS 支持打断 + 更自然的句间停顿（P2 已有规划，建议提前）。

**D-3 AI 记忆无溯源**
- 对比：Saner.AI（透明记忆，可溯源）
- 等级：**中**
- 代码状态：有但弱 —— 记忆抽取契约完整（≤20 字/条、≤5 条）、设置页可管理，但无「这条记忆哪次说的、影响了什么」。
- 建议：记忆补「来源对话时间 + 最近生效时间」两字段，设置页点开可见（也是评审时证明长期记忆闭环的最硬证据）。

- 建议：结构化比价卡（多平台价 + 历史价曲线）+ 降价提醒（已在路线图，建议提前并接 `pushPriceAlert`）。

### G. 账号 / 支付 / 多端（4 条）

**G-1 付费链路未闭环**
- 对比：滴答 / Notion（完整订阅支付）
- 等级：**高**（直接影响变现）
- 代码状态：缺失 + 资质阻塞 —— `createOrder` 只建 orders 记录、**无 `payCallback`**；`login` 永远 `subscribed:false`；个人主体开不了微信支付。
- 建议：先注册个体/企业主体 + 接 `cloudPay` 回调；主体未定前**先下线付费入口**，避免「点了付不了」。

**G-2 手机号登录缺失**
- 对比：主流 App（手机号 / 一键登录）
- 等级：**中**
- 代码状态：缺失 + 资质阻塞 —— `login` 仅 `code2Session`，手机号登录待主体认证后接。
- 建议：主体认证后接手机号/一键登录，降低流失。

**G-3 多端云同步弱、H5 体验降级为 mock**
- 对比：滴答 / Notion（多端实时云同步）
- 等级：**中**
- 代码状态：有但弱 —— 仅小程序 `cloudSync` 30s 节流上云；H5 静态托管无服务端，AI 走规则 mock，功能大幅缩水。
- 建议：统一云端身份；H5 接轻量服务端 AI，缩小与小程序端的体验差。

**G-4 无数据导出 / 备份**
- 对比：滴答（导出）/ Google Takeout
- 等级：**中**
- 代码状态：缺失 —— 无导出入口。
- 建议：提供日程/待办/收藏/记忆的 JSON 导出（合规且低成本的留存手段）。

### H. 推送 / 触达 / 微信生态（2 条）

**H-1 定时推送订阅模板 ID 空串 → 整条链路 noop**
- 对比：各类晨报 App（每日定时推送）
- 等级：**高**

- 建议：微信后台建订阅模板 → 填 `src/config/subscribe.ts:12` **和** 云函数环境变量 `SUBSCRIBE_TEMPLATE_ID` 两处（用户动作，非代码缺陷）。

**H-2 微信生态转发收集入口缺失**
- 对比：5 家竞品一致的第一收集入口（转发/分享）
- 等级：**中**

### I. 合规 / 上市资质（4 条，硬门槛）

**I-1 主体未注册 / 无 ICP 备案 / 隐私政策与用户协议未完善**
- 对比：任意上架应用（主体 + 备案 + 隐私政策）
- 等级：**高**（不解决就不能「上市」）
- 代码状态：缺失 + 资质阻塞 —— 用户已选「个体工商户 + 小程序」，执照/认证尚未办理；隐私政策/用户协议条款不全。
- 建议：办理个体/企业主体 + ICP 备案 + 完善隐私政策与用户协议（含 AI 条款、记忆隐私声明）。

**I-2 AI 类目审核 / 算法备案未做**
- 对比：上市 AI 应用（深度合成类目 + 算法备案）
- 等级：**高**
- 代码状态：部分实现 + 资质阻塞 —— 已做 AI 常驻标识（C1）、`msgSecCheck`（**因云函数未部署线上未生效**）；未做微信类目审核、算法备案（需企业主体 + 供应商盖章协议）。
- 建议：主体注册后走微信认证 + 深度合成类目 + 算法备案；先部署云函数让 `msgSecCheck` 线上生效。

**I-3 RSS 源资质未审计（缺《互联网新闻信息服务许可证》）**
- 对比：合规资讯聚合（持证）
- 等级：**中-高**
- 代码状态：部分实现 + 资质阻塞 —— `compliance-source-audit.md`（27KB）已存在，但时政/突发类需许可证与前置审批（用户/资质范畴）。
- 建议：剥离时政/突发源，或办证后接入；先把 RSS 源清单做合规审计落库。

**I-4 财经内容缺常驻免责与 AI 来源披露**
- 对比：雪球 / 东方财富（页脚常驻「不构成投资建议」）
- 等级：**中**
- 代码状态：缺失 —— `src/data/legal.ts:78` 仅通用免责，**无**页脚常驻「内容由 AI 整理，不构成投资建议」。
- 建议：晨报/热点页页脚 + 价格提醒处加常驻免责句（一行文案，合规审核点）。

### J. 数据 / 度量（1 条）

**J-1 无产品数据分析体系（We 分析未开通、无北极星埋点）**
- 对比：成熟产品（数据驱动迭代）
- 等级：**中**

## 五、建议方向汇总（按优先级）

**P0（先解决「上市/可用」硬门槛，多为资质+阻塞项）**

5. A-1 / A-2 情报溯源 + 跨源去重（留存头号杀手，纯代码可做）。

**明确不抄（差异化守卫，避免重蹈覆辙）**

- 不立项系统日历双向同步（平台无读取 API）。

## 六、结论

我们的差异化护城河是「微信转发的唯一合规收集入口 + 晨报仪式感 + 代码级人机边界」，这在上市竞品中难以被大厂复制。但 27 条不足里有 **10 条高等级缺口**，集中在四块：**① 情报质量（无溯源/无跨源去重/源窄）、② 规划深度（无重排/无负载/无周报）、③ 商业化闭环（付费未接/无手机登录/推送被空配置卡死）、④ 合规资质（无主体/无备案/算法未备）**。前两块可纯代码快速补强，后两块取决于主体资质办理进度——这正是产品方向与差距优先级的核心依据。

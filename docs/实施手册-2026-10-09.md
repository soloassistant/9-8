# 阶段 1 · 发布前端（**无外部依赖，立刻可做**）

## 做什么

让线上用上本地这份 `app.a8cbdfbb.js`，它比线上多一个修复：**免费档不再被误标「AI 提炼暂不可用」**。

## ⚠️ 执行前必须知道的一个坑

**`npm run build:h5` 会清掉 `dist/api/hotspot.json`。**

我核实过：`.tools/copy-assets.js` 只搬 PNG，**不生成 hotspot.json**；它来自 `cloud.ts` 的兜底链第 3 跳（离线兜底用）。现在线上 `/api/hotspot.json` 返回 **200 / 68,145 B**，是好的 —— 重新构建会让它消失。

兜底链是：`/api/hotspot` → `soloassistant.github.io/9-8/api/hotspot.json` → `./api/hotspot.json`。前两跳我实测都 200，所以**丢了不会立刻白屏**，但离线兜底没了。

## 步骤

```powershell
cd D:\Agent

# ① 先备份现有的 hotspot.json（构建会被清掉）
if (Test-Path dist\api\hotspot.json) { Copy-Item dist\api\hotspot.json .tools\hotspot-backup.json }

# ② 构建
npm run build:h5

# ③ 还原 hotspot.json
if (Test-Path .tools\hotspot-backup.json) { Copy-Item .tools\hotspot-backup.json dist\api\hotspot.json -Force }

# ④ 确认产物在位
Get-ChildItem dist\js\app.*.js, dist\css\app.*.css | Select-Object Name, Length
Get-ChildItem dist\api\hotspot.json
```

> ⚠️ 若 `.tools/hotspot-backup.json` 不存在（本地已被上一次构建清掉），
> 先从线上拉一份回来再构建：`curl -o dist\api\hotspot.json https://soloassistant.github.io/9-8/api/hotspot.json`

# 阶段 3 · 清理历史 bundle（发布做完后顺手做）

线上 `/js/` 现在堆着 **7 个 bundle，合计约 12.5 MB**：

```
2fedd178(当前)  a1ea5043  6ebf8f65  a790d110  d13c81e3  de9e8c49  ea4d45f2
```

**为什么该清**：

- 里面是**带 mock 云函数模块的旧代码**（`mock-openid-001` / 「晨友」）。不算致命——mock 只有被 `callFunction()` 才会执行——但对准备上市的产品是暴露面
- 排障时容易误判「我改的怎么没生效」（去翻了旧 bundle）
- 该平台部署是**覆盖式、不删除**的：新增文件只是目录里多加一个，**移出目录再发也无效**，只能靠平台侧清理

## 步骤

发布完成后，在 WorkBuddy 平台/部署配置里确认是否有「发布时清理旧产物」的选项。若没有，需要平台侧协助删除 `js/` 与 `css/` 下的历史产物。

⚠️ **删除前先确认当前 `index.html` 引用的是哪一个**，删错会把线上打挂。

## 完成判据

```powershell
curl.exe -sS "$ep/js/"   # 只应剩下当前那一个 app.*.js
```

## 1. 已经核实的事实（以及没核实的部分）

### 1.1 仓库现状

- `cloudfunctions/` 下 **27 个**云函数（与 `verify-docs.mjs` 的 C1 现查口径一致）。
- 定时触发器已有先例：`cloudfunctions/getBriefing/config.json` 里 `triggers[].type = "timer"`、7 段 cron。
- 出网已有先例：`cloudfunctions/webSearch/index.js` 用 Node 内置 `https.get` 抓 20+ 个外站 RSS（含重定向、超时、UA），**没有引入 axios/got**。→ 本方案也不新增 HTTP 依赖。
- `cloudfunctions/extract` **不是通用 OCR**：输入 `event.content`（文本）或 `event.images`（base64，≤3 张），输出 events/todos/bills/shoppingItems/vocabularies/collection/note；**没有题库 schema**。可复用它的视觉模型/`msgSecCheck` 通路，但不能直接当题库 OCR 用。

### 1.2 两端数据面（这决定了题库放哪）

- H5：`src/services/cloudDb.ts` 走 WorkBuddy 云数据库（PostgREST 兼容），表 `user_kv` / `llm_events` / `feedback`。
- 小程序：走微信云函数/微信云数据库。**H5 无法调用微信云函数**（`RPC_ALLOWLIST` 当前为空，见 `src/services/dataSource.ts`）。
- 因此题库的**唯一可同时服务两端**的位置是 **WorkBuddy 云库**：H5 直读（anon 只读），小程序经 `questionBank` 云函数代理（服务端出网读 REST）。
- `.tools/sql/v2-db-anon-revoke.sql` 已把 **anon 从用户数据表收口**（`user_kv/feedback/llm_events` 无 anon SELECT）。题库表必须**单独、显式**授予 anon 只读，且只限内容表，不能顺手放开用户表。

### 1.3 云函数出网

- 客户端 `wx.request` 受「后台配置的合法域名」限制；**服务端云函数不受这条限制**（`webSearch` 的既有实现即为证据）。
- 平台**默认不提供固定公网出口 IP**；固定出口 IP 属付费能力（官方定价页曾显示 49 元/月/环境，**以控制台现价为准**）。
- 超时：微信 CLI 文档写 1–60 秒，CloudBase API 文档写 1–900 秒。**本方案按 60 秒上限设计内部预算（45 秒）**，不赌更高值。
- **未验证**：平台是否会拦截特定域名/内容、单次响应体上限、出网并发上限。→ 上线前必须用真实环境探针跑 3 个目标 URL 并记录耗时/状态码（见 §10.3）。

### 1.4 候选站 robots 实测（2026-11-05）

| 站点 | robots 实测结果 | 许可/权利线索 | 结论 |
| --- | --- | --- | --- |

## 2. 抓取器架构

### 2.1 函数与触发器

| 函数 | 职责 | 身份门禁 | 触发器 |
| --- | --- | --- | --- |
| `crawlQuestions` | robots 预检 → 抓列表/详情 → 解析 → 归一化去重 → 规则分类 → 写入 WorkBuddy 云库 | `INTERNAL_CALL_TOKEN`（手动）；定时器走平台事件 | **MVP 不配定时器**，只手动；PR-2 再加每日 1 次 cron |
| `questionBank` | 小程序端只读代理：分页、筛选、搜索 | 无用户态，返回公开字段 | 无 |
| `takedownQuestions` | 按 `source_url` 或 `question_id` 批量下架并**用 anon key 复验** | `INTERNAL_CALL_TOKEN` | 无 |

- 函数数量：**27 → 30**。
- 新增依赖：**0**。HTTP 用 Node 内置 `https`；HTML 用自写标签扫描器（见 §3.1）。若后续证明扫描器不够用，再提 `node-html-parser`（纯 JS、无原生编译、约 40 KB），**本方案不安装**。

### 2.2 队列、断点续抓、重试、死信

MVP 用**轻量表**做队列 + 断点，不引入消息队列：

- `crawl_jobs(id, site, url, status, attempts, last_error, skipped_reason, updated_at)`
- 状态机：`pending → running → done | skipped | dead`
- 断点续抓：每次调用只取 `status='pending'` 的前 10 条；跑完写回，进程被杀也只丢当前一条。
- 重试：`attempts < 3` 回 `pending`，否则 `dead` 并记 `last_error`。
- 死信：`status='dead'` 即死信区，人工用一条 SQL/脚本重排为 `pending`。
- **MVP 简化**：首版可以只跑单批（最多 20 个 URL），`crawl_jobs` 记录本轮结果；真正的跨轮队列放 PR-2。这不影响「手动跑一次能看见结果」的目标。

### 2.3 并发、限速、熔断

- 单函数内 `MAX_CONCURRENCY = 1`（串行抓取）。
- 每站 **≤1 req/s**：`crawl_sites.last_request_at` 记录上次请求时间，取 `max(0, 1000 - elapsed)` 主动 sleep。
- 连续失败 **5 次** → 写 `crawl_sites.disabled_at + disabled_reason='5_failures'`，后续直接跳过该站并 `console.error` 留痕（`warn` 会被生产构建剔除）。
- 站点级租约：`crawl_sites.lease_until` 防止「定时器 + 手动」双跑同一站。

### 2.4 单次调用预算

- 内部预算 45 秒（平台上限按 60 秒保守设计）；单页抓取超时 10 秒，最多 2 次重定向。
- 响应体超过 2 MB 直接中断并记 `too_large`（不解析、不入库）。
- 单轮最多 20 个详情页（20 req/s 以上的量级会直接触发封禁风险）。

## 3. 解析

### 3.1 HTML 结构解析 vs 正则

**结论：MVP 用「自写标签扫描器 + 每站适配器」，不引入 DOM 库。**

理由：
1. 现有云函数零额外依赖（`wx-server-sdk` 之外没有 HTTP/HTML 库），加库要过部署与体积关。
2. 首版只对接 1 个站，结构固定，扫描器 + 站点适配器足够；引入通用 DOM 解析是为「以后可能有 10 个站」提前付费，属过度设计。
3. 风险已量化：站点改版会让正则失效 —— 用 §3.4 的 canary + 自动停站兜住，而不是靠「更聪明的解析」。

扫描器职责（约 40 行）：去 `script/style/comment` → 按块级标签切块 → 去标签 → 解码实体（`&nbsp; &amp; &#x...;`）→ 折叠空白。

**站点适配器契约**：

```js
{
  key: 'wikibooks-math',
  matches(url),                    // 只认该站允许的路径
  listUrls(html, baseUrl),         // 列表页 → 详情页 URL（同站、非 Special:）
  parseQuestions(html, url)        // → [{ stem, options[], answerKey, section }]
}
```

多站差异由适配器吸收；`crawlQuestions` 主流程不认识任何站点。

### 3.2 如何判断「这一块是题干」而不是导航/广告/页脚

打分制，**得分 ≥3 才自动入库**：

| 信号 | 加分 |
| --- | --- |
| 含问句终止符 / 空白括号 `（ ）` / 「下列、请、求、计算、阅读、材料、如图」 | +1 |
| 有 2–4 个选项标记 `A．B．C．D．`（选择题）或正文 ≥12 字且含数字/公式符号 | +1 |
| 文本块 ≥20 字，且汉字占比 ≥60%（排除导航条、按钮、页脚） | +1 |
| 块内无广告/导航/版权词 | +1 |

**一票否决**（命中即跳过）：`广告|版权|免责|客服|登录|注册|关注我们|下载APP|扫码`。

**误判兜底**：
- 得分 2 → 入 `questions` 但 `review_status='pending'`、`parse_score=2`，默认列表排后并标「待校正」。
- 得分 <2 → 不入库，写 `crawl_jobs.skipped_reason='low_score'`。
- 每题存 `adapter_key + parse_score + raw_len`，出问题能按适配器版本回溯。

### 3.3 三条硬线在解析层的落地

1. **不搬整卷排版/扫描件**：解析器只产 `stem/options/answerKey` 三类字段；`<img>` 一律丢弃；去图后正文 <6 字 → `skipped_reason='image_only'`。**不下载 PDF、不保存 HTML 原文、不保存版式。**
2. **不搬第三方解析与图片**：`解析|详解|名师|视频讲解|点睛` 段落整段丢弃；答案只保留 ≤200 字的要点（超出截断并标记 `answer_truncated`）；不存任何图片 URL。
3. **不绕过付费墙/登录墙/验证码**：页面命中 `请登录|登录后查看|购买|付费|VIP|会员|验证码|captcha|滑动验证` 且正文无有效题目 → `skipped_reason='paywall_or_login'`；**不写任何模拟登录、Cookie 注入、验证码识别代码**。重定向到登录页同样按跳过处理。

## 4. 去重

### 4.1 题干归一化

顺序固定（不可调换）：

1. 全角 → 半角（ASCII 区间）；
2. 去掉零宽字符（`\u200b-\u200f\ufeff`）；
3. 统一标点：`，。？！；：、（）「」“”‘’` → 半角对应；
4. 去掉题号前缀：`^第?\s*\d+\s*[题．.、)]`；
5. 折叠所有空白（含 `&nbsp;`）为单个空格；
6. `trim()` + 小写化（仅对拉丁字母）。

### 4.2 hash 与合并

- `content_hash = sha256(stem_norm)`，`questions.content_hash` **唯一**。
- 同题不同来源：`INSERT ... ON CONFLICT (content_hash) DO UPDATE` 只更新 `updated_at`，**不覆盖已有选项/答案**（避免不同站答案冲突把好数据改坏）。
- 来源合并进 `question_sources`，唯一键 `(question_id, source_url)`；重复来源只更新 `fetched_at`。
- 选项/答案冲突：保留首次值，置 `questions.has_conflict=true` 并进人工复核队列；UI 显示「多来源答案存在差异」时不展示答案。

## 5. 分类

### 5.1 枚举 vs 自由标签

| 维度 | 形态 | 取值 |
| --- | --- | --- |
| 学科 | 枚举 | `math/chinese/english/physics/chemistry/biology/history/geography/politics` |
| 年级 | 枚举（学段）+ 短标签 | `primary/junior/senior` + `grade_label`（如「高一」） |
| 题型 | 枚举 | `single_choice/multi_choice/fill_blank/short_answer/essay/judge` |
| 难度 | 枚举 | `easy/medium/hard/unknown` |
| 知识点 | **闭集字典**（代码内维护，≈40 个数学标签） | 未知 → `['未归类']` |

- **不允许自由标签入库**。`knowledge_tags` 元素必须在字典内，入库前逐项校验，不在字典 → 丢弃该标签（不是丢题）。
- 防标签爆炸：单题 ≤5 个标签；新增标签必须改代码字典并过 review，不能由抓取结果自动扩张。

### 5.2 规则优先，LLM 兜底

- **规则**（默认）：章节面包屑 + 关键词表 + 题型标记（`A．` 选项 → 选择题；`（ ）` → 填空；`解答下列` → 解答题）。规则给出 `classify_confidence`。
- **LLM**（默认关闭）：仅当 `confidence < 0.6` 且环境变量 `LLM_API_KEY` 存在时调用一次；prompt 要求**只返回枚举值**；返回后逐字段校验，任一字段不在枚举 → 整次判定作废，回落 `pending`。
- **fail-closed**：LLM 超时/限流/JSON 不合法/字段越界 → **不猜**，保持规则结果并置 `pending`。抓取流程不因分类失败而失败。
- 成本：只对低置信度子集调用（估算 <30% 题量）；单题 prompt ≈700 tokens、输出 ≤200 tokens；按现有 `chat` 模型单价，单题成本在「千分之几元」量级，**以实际账单为准**。
- Key 来源：复用云函数已有的 `LLM_API_KEY` 环境变量（`chat`/`extract` 在用）。**不要**新增前端可见的 key。

### 5.3 人工改与回退

- `questions` 上：`classify_source ∈ rule|llm|human`、`classify_confidence`、`review_status ∈ pending|approved|rejected`。
- `question_review_log(question_id, field, before, after, actor, created_at)` **只增不改**。
- 人工改 = 写新值 + 写日志；回退 = 把日志里的 `before` 写回 + 再写一条新日志（重放，不删历史）。
- 低置信度处理：`pending` 默认**可见但排后、带「待校正」标记**（是否改为「仅内部可见」见 §12 第 7 条）。

## 6. 入库与读

### 6.1 表结构（WorkBuddy 云库 / PostgREST）

```sql
-- 题目：全局内容，无 owner_id，不进 user_kv
CREATE TABLE questions (
  id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  content_hash   TEXT UNIQUE NOT NULL,
  stem           TEXT NOT NULL,
  stem_norm      TEXT NOT NULL,
  options        JSONB NOT NULL DEFAULT '[]',   -- [{key:'A',text:'...'}] ≤ 8 项
  answer_key     TEXT,                          -- 只存要点，≤200 字；无答案则 NULL
  subject        TEXT NOT NULL,
  grade_band     TEXT,
  grade_label    TEXT,
  qtype          TEXT,
  difficulty     TEXT NOT NULL DEFAULT 'unknown',
  knowledge_tags TEXT[] NOT NULL DEFAULT '{}',
  parse_score    SMALLINT NOT NULL DEFAULT 0,
  review_status  TEXT NOT NULL DEFAULT 'pending',
  classify_source TEXT NOT NULL DEFAULT 'rule',
  classify_confidence REAL NOT NULL DEFAULT 0,
  has_conflict   BOOLEAN NOT NULL DEFAULT false,
  source_site    TEXT NOT NULL,
  source_url     TEXT NOT NULL,
  fetched_at     TIMESTAMPTZ NOT NULL,
  robots_ok      BOOLEAN NOT NULL,
  license_note   TEXT,
  deleted_at     TIMESTAMPTZ,
  created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 多来源：一题多源，不重复存题
CREATE TABLE question_sources (
  question_id UUID NOT NULL REFERENCES questions(id) ON DELETE CASCADE,
  source_url  TEXT NOT NULL,
  source_site TEXT NOT NULL,
  fetched_at  TIMESTAMPTZ NOT NULL,
  robots_ok   BOOLEAN NOT NULL,
  PRIMARY KEY (question_id, source_url)
);

-- 抓取站点：robots 缓存 + 限速 + 熔断 + 租约
CREATE TABLE crawl_sites (
  site              TEXT PRIMARY KEY,
  robots_txt        TEXT,
  robots_checked_at TIMESTAMPTZ,
  robots_ok         BOOLEAN NOT NULL DEFAULT false,
  last_request_at   TIMESTAMPTZ,
  consecutive_failures INT NOT NULL DEFAULT 0,
  lease_until       TIMESTAMPTZ,
  disabled_at       TIMESTAMPTZ,
  disabled_reason   TEXT
);

-- 队列/断点/死信
CREATE TABLE crawl_jobs (
  id            BIGSERIAL PRIMARY KEY,
  site          TEXT NOT NULL,
  url           TEXT NOT NULL,
  status        TEXT NOT NULL DEFAULT 'pending',  -- pending|running|done|skipped|dead
  attempts      INT NOT NULL DEFAULT 0,
  skipped_reason TEXT,
  last_error    TEXT,
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 下架记录（只增不改）
CREATE TABLE takedowns (
  id          BIGSERIAL PRIMARY KEY,
  scope_type  TEXT NOT NULL,   -- source_url | question_id
  scope_value TEXT NOT NULL,
  reason      TEXT NOT NULL,
  actor       TEXT NOT NULL,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  removed_rows INT NOT NULL DEFAULT 0
);

-- 人工改与回退（只增不改）
CREATE TABLE question_review_log (
  id          BIGSERIAL PRIMARY KEY,
  question_id UUID NOT NULL REFERENCES questions(id) ON DELETE CASCADE,
  field       TEXT NOT NULL,
  before_value TEXT,
  after_value  TEXT,
  actor       TEXT NOT NULL,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

索引：

```sql
CREATE INDEX questions_public_list ON questions (subject, grade_band, qtype, created_at DESC)
  WHERE deleted_at IS NULL;
CREATE INDEX questions_source_site ON questions (source_site, fetched_at DESC);
CREATE INDEX questions_tags ON questions USING GIN (knowledge_tags);
CREATE INDEX crawl_jobs_pending ON crawl_jobs (site, status, id) WHERE status = 'pending';
```

### 6.2 RLS 与授权（关键：只开内容读，不开任何写）

```sql
ALTER TABLE questions ENABLE ROW LEVEL SECURITY;
ALTER TABLE question_sources ENABLE ROW LEVEL SECURITY;

-- 内容表：anon / authenticated 只读，且只读未下架的
GRANT SELECT ON public.questions TO anon, authenticated;
GRANT SELECT ON public.question_sources TO anon, authenticated;

CREATE POLICY questions_public_read ON public.questions
  FOR SELECT TO anon, authenticated
  USING (deleted_at IS NULL);

-- 其余四张表：任何客户端角色零授权（默认可能是开放的，必须显式收回）
REVOKE ALL ON TABLE public.crawl_jobs, public.crawl_sites,
  public.takedowns, public.question_review_log FROM anon, authenticated, PUBLIC;
GRANT ALL ON TABLE public.crawl_jobs, public.crawl_sites,
  public.takedowns, public.question_review_log TO service_role;
```

- **写路径只有 service_role**（云函数持密钥），前端与匿名用户无 INSERT/UPDATE/DELETE 授权。
- 断言（改坏必红）：
  - anon `INSERT questions` → 42501；
  - anon `SELECT crawl_jobs` → 42501；
  - anon `SELECT questions` 在题被下架后返回 0 行。
- 用户数据表（`user_kv/feedback/llm_events`）**保持 v2 的 anon 收口**，题库迁移不得重新放开。

### 6.3 前端只读库

- H5：新增 `src/services/questionBank.ts`（约 60 行），走 `cloudDb` 同款 SDK：`db.from('questions').select(...).eq('subject','math').order('created_at',{ascending:false}).range(...)`。
- 小程序：`questionBank` 云函数用 service_role 读 PostgREST，返回**白名单字段**（不含 `content_hash` / `review_status` 等内部字段），分页 20 条。
- **前端不直连任何外网**：抓取只发生在 `crawlQuestions` 内；小程序不新增合法域名；H5 只访问 WorkBuddy 云库（既有通路）。
- 分页与搜索：`range(0,19)`；搜索用 `stem_norm ILIKE '%kw%'`（MVP 数据量 <2 万，无 trgm 索引也够；超 5 万再评估）。
- **不进 `SYNC_KEYS` / `user_kv`**：题库是全局内容，没有 per-key 时间戳、没有「新者胜」、没有客户端推送。这条要在门禁里断言，防止有人图省事把它塞进 `cloudSync`（那会重演「先推后拉」与 512KB 单键问题）。

## 7. 下架机制

### 7.1 命令

```bash
# 按来源 URL
node .tools/qb-takedown.mjs --url "<source_url>" --reason "版权方要求" --actor "ops"

# 按题目标识（content_hash 或 id）
node .tools/qb-takedown.mjs --hash "<content_hash>" --reason "误分类" --actor "ops"
```

脚本只做一件事：调 `takedownQuestions` 云函数（带 `INTERNAL_CALL_TOKEN`）。

### 7.2 云函数执行顺序

1. 写 `takedowns` 记录（先留痕，再删数据）；
2. `scope=source_url`：删 `question_sources` 中该 URL；对因此**零来源**的题，硬删 `questions` 行（`ON DELETE CASCADE` 清 sources）；
3. `scope=question_id/hash`：硬删该题及级联来源；
4. **复验**：用 **publishable/anon key** 再查一次
   `GET /rest/questions?content_hash=eq.<hash>&deleted_at=is.null` 与
   `GET /rest/question_sources?source_url=eq.<url>`，要求 `Content-Range` 计数为 `0`；
5. 把复验结果写回 `takedowns.removed_rows`，返回 `{ removed, remaining_public: 0 }`；**复验不为 0 则命令失败退出**（不允许「删了但读得到」）。

> 为什么用 anon 复验：service_role 会绕过 RLS，用它会得到「删了/没删都看不见」的假证明。anon 复验才是用户真实读路径。

## 8. 合规留痕

每题至少记：`source_site`、`source_url`、`fetched_at`、`robots_ok`、`license_note`；来源 URL 同时进 `question_sources`（多来源可追溯）。

用户可见处展示：
- 列表项底部固定显示 `来源：<source_site> · <fetched_at 日期>`；
- 详情/展开处显示完整 `source_url` 文本（可复制；点击是新标签打开，不经过抓取通道）；
- 多来源时显示「另有 N 个来源」，展开可看；
- **不显示**第三方解析、不内嵌第三方图片、不代理第三方资源。

同时保留：
- `robots_ok=false` 的站点**一律不抓**（fail-closed），不会有「无 robots 也抓」的分支；
- 站点被 `disabled_at` 标记后，`crawl_jobs` 新增行直接 `skipped_reason='site_disabled'`。

## 9. 三条硬线在代码里的落点

| 硬线 | 落点 | 具体做法 | 对应断言 |
| --- | --- | --- | --- |
| 1 不搬整卷排版/扫描件 | `cloudfunctions/crawlQuestions/lib/parse.js` 顶部注释 + `v7-questionbank.sql` | 只产 `stem/options/answerKey`；丢 `<img>`；不建 PDF/图片/HTML 原文字段；表结构无 `raw_html` 列 | 给 `questions` 加 `raw_html` 列 → 断言红；解析结果含 `image` 字段 → 断言红 |
| 2 不搬第三方解析/图片 | `lib/parse.js` 的 `stripAnalysis()` + 入库前 `sanitize()` | 命中「解析/详解/名师/视频」的段落整段丢弃；答案截断 ≤200 字；不存图片 URL | 把 `解析` 段塞进 `answer_key` → 断言红 |
| 3 不绕付费墙/登录墙/验证码 | `cloudfunctions/crawlQuestions/lib/guard.js` + `parse.js` | 命中登录/付费/验证码标记 → `skipped_reason='paywall_or_login'`；重定向到登录页同样跳过；**不含登录模拟代码** | 删掉跳过分支 → 断言红（构造含「请登录后查看」的 fixture） |

工程约束落点：

| 约束 | 落点 |
| --- | --- |
| 遵守 robots | `lib/guard.js` `robotsAllows(site, path)`；无有效 robots（404/挑战页/TLS 失败）→ 整站跳过 |
| 每站 ≤1 req/s | `crawl_sites.last_request_at` + `sleep(1000 - elapsed)`；断言：连抓 3 页总耗时 ≥2s |
| 连续失败 5 次停站 | `consecutive_failures >= 5` → `disabled_at` + `console.error`；断言：第 6 次不发请求 |

## 10. 我最担心的三件事

### 10.1 站点改版导致解析全面失效

- **为什么怕**：解析靠站点结构；改版当天可能「抓得到、抽不出」，而且**静默**——不报错，只是产出 0 条。
- **缓解**：每站固定 3 个 canary URL，每次运行先跑 canary；产出率 < 上次基线的 50% → 自动 `disabled_at='parse_regression'` + 告警日志；`parse_score` 分布突变同样触发。
- **残余风险**：canary 通过但新页面结构不同 → 部分题抽取错误，靠 `pending` + 人工复核兜底。**不可能做到 100% 正确。**

### 10.2 被封 IP / 收到律师函

- **为什么怕**：默认无固定出口 IP，封了就是整个环境受影响；律师函是业务风险，代码无法消除。
- **缓解**：≤1 req/s、串行、UA 带项目标识、遵守 robots、只存结构化字段、来源留痕、48 小时内可下架、`takedowns` 留证。
- **残余风险**：**方案不承诺不被封、不承诺不侵权**。若目标站明确禁止转载或发函，唯一正确动作是停抓并下架，不是换 IP 继续。

### 10.3 微信云函数出网与写入 WorkBuddy 的真实限制

- **已核实**：服务端出网可用（`webSearch` 现有实现）；默认无固定出口 IP；60 秒超时上限按保守口径。
- **未核实**：平台是否拦截特定域名/内容、响应体上限、并发上限；以及**云函数拿不到 WorkBuddy 的 service_role key 时，写入根本走不通**（仓库目前只有 `INTERNAL_CALL_TOKEN`，没有任何 `WORKBUDDY_*` 密钥）。
- **缓解**：
  - 上线前用真实云函数跑探针（3 个目标 URL，记录状态码/耗时/字节数）；
  - 若拿不到 service key → **备选路径 B**：GitHub Actions 跑同一套抓取代码，产出分片 JSON 到 gh-pages；H5 读同源静态 JSON，小程序经 `questionBank` 云函数拉该 JSON。代价：没有 SQL 分页/搜索，改为客户端索引；下架靠重新生成快照（可证明：新版快照里 0 条）。
  - 备选路径 B 不依赖任何新密钥，但**「能证明下架后读不到」要等快照重新发布**，时效性差于数据库方案。
- **残余风险**：出网稳定性和平台策略只能靠真实环境验证，方案阶段无法证明。

### 11.1 做什么

4. 构造含「请登录后查看」的 fixture → `skipped_reason='paywall_or_login'`，`questions` 不新增；

6. 把「跳过登录墙」分支删掉 → 断言红（不是 grep，而是跑 fixture 看行为）。

## 14. 其他被明确排除的路径

- **前端直连外网**：不做。小程序合法域名白名单、H5 跨域、密钥泄漏三重风险。
- **把题库塞进 `cloudSync`/`user_kv`**：不做。全局内容没有 owner，且会重演「先推后拉」与 512KB 单键上限。
- **爬虫写微信云数据库再由 H5 读**：不做。H5 无微信云函数通道。
- **抓 zxxk / jyeoo / pep / tiku.gaokao.com**：不做（反爬挑战 / 付费墙 / 无有效 robots / 证书失败）。
- **保存整卷 HTML / PDF / 图片**：不做（硬线 1）。
- **保存第三方长解析 / 名师讲解 / 水印图**：不做（硬线 2）。
- **模拟登录 / Cookie 注入 / 验证码识别**：不做（硬线 3）。

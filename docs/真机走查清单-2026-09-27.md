# 真机走查清单（2026-09-27 · 本战役全部新特性）

> 用途：真机（微信小程序）+ H5 双端预览走查，覆盖战役 A–G、竞品改进 16 项与 v1.3 遗留语音项。
> 每条：操作步骤 → 预期结果 → 涉及代码。走完一条勾一条，全部通过后方可提审。

## 前置条件

1. **云函数已部署**：按 `docs/云函数部署指南.md` 路径 A（`npm run deploy:cloud`）或路径 B 上传 12 个函数，云开发控制台确认全部「部署成功」。
2. **订阅模板 id 已配置**：微信公众平台 → 功能 → 订阅消息 → 选用「一次性订阅」模板，复制模板 id 后**两处同填**：① `src/config/subscribe.ts` 的 `SUBSCRIBE_TEMPLATE_ID`；② 云函数 `getBriefing` 的环境变量 `SUBSCRIBE_TEMPLATE_ID`（同见部署指南）。
3. **真机预览二维码**：微信开发者工具打开本项目 → 工具栏「预览」→ 用绑定该小程序的微信扫码（游客 appid 无法真机预览，需真实 AppID）。
4. H5 走查：`npm run build:h5` 后本地访问 dist（或开发态 `npm run dev:h5`）。

## 战役 A–G

| 特性 | 操作步骤 | 预期结果 | 涉及代码 |
|------|---------|---------|---------|
| A 记忆回灌 | 对 AI 助理说「记住我喜欢早上9点后安排会议」→ 新开一轮对话说「帮我排个会」 | 助理排会时段不早于 9:00（遵守已存偏好）；日志可见 memories 注入 | `src/components/AiAssistant/index.tsx`（readMemory→apiChat memories）、`cloudfunctions/chat/index.js`（MEMORY_RECALL_PROMPT） |
| B 搜索扩面 | 问「今天有什么热点」→ 再问购物对比类（如「XX 和 YY 哪个好」） | 两类意图均返回带来源标注的联网搜索结果，非凭空作答 | `cloudfunctions/chat/index.js`（NEWS_SEARCH_INTENT / webSearchReply） |
| C 日历一键重排 | 日历页造 2 条重叠日程 → 进入日历页看冲突条 → 点一键重排 → 勾选批准 | 出现重排方案卡；批准后日程落库且冲突消除；方案时间与相邻日程 ≥10 分钟间隙 | `src/pages/calendar/index.tsx`（conflictCount / apiApplyPlan）、`src/components/PlanProposalCard/index.tsx` |
| D 负载条 | 造一个多日程/长日程的日子 → 打开晨报 | 晨报出现按当日总时长计算的忙碌程度负载条；清空日程后负载回落 | `cloudfunctions/getBriefing/index.js` + `src/utils/adaptive.ts`（busyMinutes 同口径） |
| E 记忆溯源 | 有记忆的前提下让 AI 回答一条需参考偏好的问题 → 点回复下方溯源标注 | 回复下方显示「本回复已参考 {n} 条记忆」，展开可见引用的记忆明细 | `src/components/AiAssistant/index.tsx`（memoryCount / memoryItems） |
| F 10 分钟缓冲 | 把日程排满某时段 → 让 AI 往该时段附近排新事项 | 候选优先落带间隙时段；全部无间隙时方案卡顶部出现「部分时段已排满，以下条目未保留 10 分钟间隙」提示 | `src/utils/schedule.ts`（pickCandidates / noBufferFallback）、`PlanProposalCard`（plan.noBufferNote） |
| G 周复盘 | 完成若干待办与日程后（或本地造历史数据）→ 晨报页/我的页查看周复盘 | 出现按周汇总的完成情况（todosDone/事件数/关键词），无历史数据时不渲染不报错 | `src/utils/weeklyReview.ts`、`src/pages/briefing/index.tsx`、`src/pages/mine/index.tsx` |

# 多语种学习平台独立化实施方案

## 1. 方案目标

在不改动学生作品主体框架的前提下，将多语种学习功能发展为一个可以独立开发、独立构建、独立部署和独立展示的学习子产品。

主产品继续作为宿主应用，通过内部路由、外部 URL 或后续平台跳转接入学习平台。

本方案默认以“独立 Web MVP 展示版”作为第一交付目标。主产品继续使用 Taro、React 和 TypeScript；学习平台的独立 Web 展示端使用 React、Vite 和 React Router，不要求重写主产品。

首次实测暴露的三个问题及处置（2026-09-16）：

| 问题 | 现象 | 处置 |
| --- | --- | --- |
| SPA 回退吞掉 `robots.txt` | `/robots.txt` 返回 200 的 HTML，测试站可被搜索引擎完整收录且无法用 robots 控制 | 新增 `public/robots.txt` 真实文件（`Disallow: /` + 主要中文搜索引擎显式声明）；`index.html` 加 `noindex` 元信息；`_headers` 加 `X-Robots-Tag`。三重保险 |
| 安全响应头全缺 | `X-Frame-Options`/`X-Content-Type-Options`/`Referrer-Policy`/`Permissions-Policy` 实测为空；`Cache-Control` 也为空 | 新增 `public/_headers`（Cloudflare Pages 格式）声明全套安全头与缓存策略；`vercel.learning.json` 同步补齐 headers |
| 缺移动端社交元信息 | 无 `og:*`/`twitter:card`/favicon/apple-touch-icon，分享为裸链接 | `index.html` 补齐 OG/Twitter/图标元信息，分享封面用 `share-cover.png`（1024×768，符合 OG 推荐比例） |

路由模式决策：`BrowserRouter` → **`HashRouter`**。本应用是纯静态托管，HashRouter 下任意深链接
刷新都不依赖服务端 rewrite，消除了 history 模式在非根路径部署时的路径歧义。代价是 URL 带 `#`。

> 注意：`robots.txt` 与 `_headers` 必须是构建产物根目录下的**真实文件**。若缺失，SPA 的
> catch-all 回退会让这些路径返回 `index.html`，索引控制会静默失效。已加入 `apps/learning-web/README.md`
> 的部署检查清单。

尚未完成：微信开发者工具真机预览、多浏览器（尤其 iOS Safari 与微信内置浏览器）交互验收、
Cloudflare 侧 `_headers` 实际生效验证（需重新部署后复测响应头）、依赖真实用户的学习流程长跑验证。

### 依赖安装陷阱（已踩，务必避免）

不要在仓库里执行 `yarn install --ignore-scripts`。`@swc/core` 的原生平台绑定
（`@swc/core-win32-x64-msvc` 等）依赖其 `postinstall` 安装；跳过脚本后 `@swc/core` 会回退到
`@swc/wasm` 路径，触发 `Error: unknown field 'cwd'`，表现为 Taro 构建在加载
`@tarojs/cli/dist/presets/index.js` 时失败（`插件依赖 ... 加载失败`），与学习平台代码无关但会
阻断全部 Taro 构建。修复方式：删除 `node_modules/.yarn-integrity` 后执行
`yarn install --force`。构建前若怀疑依赖树受损，可先检查 `node_modules/@swc/` 下是否存在
`core-win32-x64-msvc`（Windows）。

> Git 分支只是开发边界，不能直接作为运行时依赖。真正的独立性需要通过独立入口、独立构建产物、独立数据接口和最小宿主接入实现。

## 2. 目标架构

```text
主产品
  └── 学习平台入口适配器
        ├── 同一小程序内的过渡路由
        └── 独立 Web URL

学习平台
  ├── 独立 Web 应用
  ├── 可选的 Taro 过渡页面
  ├── 独立页面与样式
  ├── 独立课程数据
  ├── 独立学习状态
  ├── 独立成就与社区
  ├── 纯 TypeScript 学习核心
  ├── 本地数据适配器
  └── 未来云端 API 适配器
```

主产品只依赖学习平台的公开入口，不直接依赖课程数据、学习 storage、成就算法或社区数据结构。

## 3. 当前分支基础

当前分支已经完成第一轮模块移动：

- `src/features/learning` 负责学习平台的宿主适配、页面、路由定义与公共入口；学习领域逻辑与数据由 `packages/learning-core` 提供。
- `src/pages/learn`、`src/pages/learnDetail`、`src/pages/learnCommunity` 保留为 Taro 路由适配入口。
- `src/app.config.ts` 负责在宿主小程序中注册学习页面。
- 主产品通过学习平台路由常量进入学习功能。

Taro 学习页面已改用 `LocalLearningRepository` + Taro storage 适配器（`src/features/learning/adapters/taro-storage.ts`），与独立 Web 展示版共享同一份进度、成就与社区逻辑；云同步也已改为只通过 `host-sync.ts` 取 key 名，不再读取学习存储实现。仍然保留的宿主依赖只有全局语言 store、`EmptyState` 组件和日期工具，这些在后续阶段收紧。

## 4. 实施阶段

### P0：冻结边界与公共接口

目标：明确哪些内容属于宿主，哪些内容属于学习平台。

工作内容：

- 保留 `src/features/learning` 作为当前开发边界。
- 明确学习平台对外公开接口，只暴露入口、路由和必要的摘要能力。
- 收紧 `src/features/learning/index.ts`，避免宿主绕过公开接口直接引用内部文件。
- 登记宿主与学习平台之间的三个真实接入点：
  - `src/app.config.ts`：同一 Taro 应用中的页面注册。
  - `src/pages/mine/index.tsx`：主产品中的学习入口跳转。
  - `src/services/cloudSync.ts`：现存学习进度同步耦合，列为 P1 首要改造对象。
- 将 `src/pages/learn*` 下的 Taro 路由适配文件视为页面基础设施，不允许承载学习业务逻辑。
- 增加学习边界检查：以独立脚本 `scripts/check-learning-boundary.js` 作为主机制，脚本不依赖现有 ESLint 配置，可在构建前运行；ESLint `no-restricted-imports` 作为可选补充，需先补齐仓库目前尚不存在的 ESLint 配置和 `lint` 脚本。
- 暂不重构晨报、收件箱、日历、热点和购物模块。

公开接口白名单：

- 通用学习接口：`LEARNING_ROUTES`、`getLearningSummary()` 及必要的公开类型。
- 宿主适配接口：`LEARNING_PAGE_PATHS` 和当前宿主页面映射，只供 `app.config.ts` 使用。
- 内部实现：`LEARN_LANGS`、`readLearnStore`、`getLangStats`、`getStreak`、`markWords`、`getUnlockedCount` 以及 storage 和成就内部类型均不对宿主公开。

公共入口预期保持为显式白名单，而不是 `export *`：

```ts
export { LEARNING_ROUTES } from './routes';
export { getLearningSummary } from './application/summary';
export type { LearningSummary } from './application/summary';
```

`LEARNING_PAGE_PATHS` 和 `/pages/...` 的当前宿主映射放入 host adapter，例如 `src/pages/learn/routes.host.ts`；独立 Web 应用使用自己的 Web 路由，不复用宿主页面路径。

边界检查规则按符号和允许的适配形式定义，不简单按目录一刀切：

- `src/app.config.ts` 可以从宿主适配器导入 `LEARNING_PAGE_PATHS`，用于同一 Taro 应用的页面注册。
- `src/pages/learn*` 下的适配文件只允许使用 `export { default } from '@/features/learning/pages/...'` 形式，不得增加学习业务逻辑或读取内部数据。
- `src/pages/mine/index.tsx` 只能调用公开的学习入口或路由适配器，不得导入 `readLearnStore`、`LEARN_LANGS`、`markWords`、`LEARNING_STORAGE_KEYS` 等内部符号。
- `src/services/cloudSync.ts` 不得深度导入学习平台内部 storage；学习同步只能通过公开同步适配器或注册接口完成。
- 学习平台内部页面可以访问自己的 domain、application 和 adapter，但不得反向依赖主产品页面。

验收标准：

- 新增宿主代码不得直接读取学习课程数据、学习进度和成就算法；现存 `cloudSync.ts` 耦合登记为 P1 待清项。
- 学习模块内部文件可以继续调整，而不需要同步修改主产品业务页面。
- 宿主接入代码保持在上述明确文件内，边界检查能够识别非法符号引用、非法深度引用和不符合形式的 Taro 薄适配器。

### P2：建立独立 Web MVP 应用

目标：学习平台可以作为独立 Web 应用启动、展示和试用，不加载主产品的 TabBar、AI 助手、Splash 或其他页面。

本阶段不再采用“同仓双配置 Taro H5”作为独立展示方案。主产品保持现有单根 Taro 工程；学习平台新增一个真正拥有独立配置和依赖边界的 Web 应用。仓库可以先采用轻量 monorepo/多包结构，但不能只创建一个未纳入 `tsconfig.json`、别名和依赖管理的 `apps/` 目录就宣称独立。

推荐结构：

```text
apps/
  learning-web/
    src/
      app/
      pages/
      components/
      adapters/
      main.tsx
    index.html
    vite.config.ts
    tsconfig.json
    package.json

packages/
  learning-core/
    domain/
    application/
    contracts/
    data/
```

主产品现有根目录继续作为 Taro 宿主，不迁移到 `apps/host-taro/`。如果采用 workspace，需要明确加入根 `package.json`、锁文件、TypeScript project references 或等价的类型检查配置，确保 `apps/learning-web` 和 `packages/learning-core` 不脱离工程保护。

独立 Web 应用技术栈：

- React + TypeScript：复用现有团队能力。
- Vite：负责快速开发、生产构建和静态部署。
- React Router：负责独立 Web URL 和页面导航。
- CSS Modules 或学习平台自己的样式层：不依赖主产品全局样式。
- 本地展示版使用 `LocalLearningRepository`，不要求登录和后端。

React 官方将 Vite + React Router 列为可行的 React 应用路线；React Router 官方也提供了基于 Vite 的启动方式。[React 创建应用指南](https://react.dev/learn/creating-a-react-app)、[React Router 安装指南](https://reactrouter.com/start/declarative/installation)

独立 Web 应用需要拥有：

- 独立启动入口。
- 独立页面和 URL 注册。
- 独立导航和返回逻辑。
- 独立标题、Logo 和展示文案。
- 独立加载页、空状态和错误页。
- 独立环境变量配置。
- 独立构建命令和输出目录，例如 `dist-learning`。
- 独立的 `projectName`、页面标题和品牌配置，不能继续使用模板名 `taro_template`。
- 独立的 Web 路由，不复用主产品的 `/pages/...` 路径。

Taro 学习页面的处理方式：

- 当前 Taro 学习页面保留为主产品内的过渡/兼容入口，直到 Web 版完成验收。
- Web 版不直接复用 `@tarojs/components` 页面 UI；只复用去宿主化后的 `learning-core`、数据模型和 repository。
- 主产品小程序继续使用自己的页面注册，不引入 `TARO_LEARNING` 条件分支，避免 weapp 构建时出现 `app.json` 页面丢失风险。
- Web 版拥有自己的导航兜底，不允许出现 `switchTab('/pages/mine/index')` 等宿主路由字面量。

独立展示版第一期保留以下功能：

1. 语言选择。
2. 课程列表。
3. 课程详情。
4. 单词掌握。
5. 学习进度。
6. 成就展示。
7. 社区展示或社区入口。

第一期暂不加载：

- 晨报 TabBar。
- 主产品 AI 悬浮助手。
- 主产品 Splash。
- 日历、购物、热点等页面。
- 主产品云同步逻辑。

构建与部署要求：

- 新增 `build:learning:web`、`dev:learning:web`、`preview:learning:web` 等脚本。
- 使用 Vite 的 `build.outDir = 'dist-learning'`，不复用主产品的 Taro `dist`。
- 修复或替换当前缺失的 `.tools/copy-assets.js`，但独立 Web 构建不能依赖主产品的资产复制脚本才能完成。
- 增加学习平台专用的 Vercel 配置，例如 `vercel.learning.json`，将 `outputDirectory` 指向 `dist-learning`。
- 增加或参数化学习平台部署脚本，例如 `deploy-learning.ps1`，使用 `dist-learning` 而不是主产品的 `dist`。
- 在 `.vercelignore` 中明确排除不属于当前部署目标的产物，至少检查 `dist` 与 `dist-learning` 的隔离规则。
- 主产品现有 `vercel.json` 和 `deploy.ps1` 的 `dist` 默认值保持不变，避免影响主体框架发布。

首期数据边界必须明确：独立 Web 与微信小程序的 localStorage/storage 互相隔离，展示版进度默认不互通。这是第一期展示定位下的已知限制，不应被误认为部署故障；跨端同步不仅依赖 P3 的远程 repository，还依赖账号体系，属于 P4 之后的工作。

验收标准：

- 浏览器直接打开独立 Web 地址即可展示学习平台，不需要先进入晨报主产品。
- 在干净浏览器中可以完成语言选择、课程浏览、单词标记、进度查看和社区展示。
- 刷新页面后，本地展示版的学习进度仍然保留。
- 首次进入独立 Web 时，课程、成就和社区都有明确的展示数据；社区种子内容应标注为演示内容，不伪装成真实用户动态。
- `dist-learning/index.html` 和静态资源可以独立部署，不覆盖主产品的 `dist`。
- 独立 Web 构建不依赖主产品页面、Taro TabBar、AI 助手或 Splash。
- 独立 Web 的课程完成和返回逻辑不会尝试跳转 `/pages/mine/index`。
- 宿主 weapp 构建模式下，生成的 `dist/app.json` 仍包含原有 3 个学习页面路径；该项用于验证过渡入口没有被 Web 化改造误伤。

### P3：建立学习数据接口

目标：让展示版和正式版可以使用不同数据来源，但共享同一套业务逻辑。

先定义学习数据接口：

```text
LearningRepository
  ├── getLanguages()
  ├── getCourse(courseId)
  ├── getCourseProgress(courseId)
  ├── markWords(courseId, wordIds, learned)
  ├── completeCourse(courseId)
  ├── setActiveLanguage(langId)
  ├── getAchievements()
  ├── getCommunityPosts()
  ├── addPost(payload)
  ├── toggleLike(postId)
  └── setLearnerName(name)
```

接口按领域动作设计，不暴露 `getProgress()` / `saveProgress()` 这种整包 blob 读写。当前本地适配器内部仍可以使用一个 `learnStore` 兼容已有数据，但远程适配器必须能够按课程、单词和社区动态进行细粒度写入。

`getRecommendedPath(langId, repository)` 是纯规则计算，不属于 repository。它由 application/domain 层调用 `getCourseProgress(courseId)` 等数据接口后完成计算，避免 `RemoteLearningRepository` 被迫实现与网络数据源无关的逻辑。（实现落点：`packages/learning-core/src/repository.ts`，签名需显式传入 repository。）

实现两套适配器：

```text
LocalLearningRepository
  └── 静态课程数据 + localStorage

RemoteLearningRepository
  └── 云函数或独立 API + 数据库
```

数据演进方向：

- `languages`
- `courses`
- `lessons`
- `words`
- `user_progress`
- `user_word_states`
- `achievements`
- `community_posts`

当前的 `learnStore` 继续作为本地展示版适配器，保持已有进度兼容；正式平台不以单个 storage blob 作为长期数据模型。

现有推荐路径引擎保留在学习平台内部，职责仍是“续学未完成课 > 间隔复习 > 开启新课”。它属于规则型 application/domain 能力，不等同于尚未实现的 SM-2 等复杂算法。

验收标准：

- 更换数据适配器不会修改学习页面的主要业务逻辑。
- 本地展示版不依赖登录和后端即可运行。
- repository 接口覆盖学习进度、推荐路径、成就和社区写入，不以整包覆盖作为远程同步的唯一方式。
- 未来接入账号和云端同步时，不需要重写课程页面。

### P4：独立 Web 部署与展示

目标：产生一个可以对外访问的学习平台地址。

第一期建议部署为独立静态 Web 应用：

```text
learning.example.com
```

或：

```text
example.com/learning/
```

部署内容包括：

- 独立构建产物。
- 独立部署配置（`vercel.learning.json`、`deploy-learning.ps1` 或等价配置）。
- 独立页面标题和 Logo。
- 独立 README 和运行说明。
- 演示数据或免登录模式。
- 独立的错误与降级提示。

部署前必须分别验证：

- 构建成功：生成 `dist-learning/index.html` 和完整静态资源。
- 部署成功：服务器或托管平台接收的是 `dist-learning`，没有误用主产品 `dist`。
- 页面可访问：从干净浏览器直接打开独立地址，完成语言选择、课程浏览、单词标记和社区展示。
- 数据限制已标注：首期独立 Web 与小程序端进度不互通。

展示版与正式版要明确区分：

- 展示版：静态课程数据、本地进度、无需登录，优先保证可访问和可演示。
- 正式版：账号、云端进度、学习记录、社区写入和数据分析。

### P5：主产品最小接入

目标：主产品可以调用或跳转学习平台，但不接管学习平台内部业务。

主产品只保留三类接入能力：

1. 页面注册：同一 Taro 应用内使用学习页面。
2. 入口跳转：通过公开路由或独立 Web URL 进入学习平台。
3. 可选摘要：通过 `getLearningSummary()` 展示最近学习课程、当前语种、已掌握词数和连续学习天数等轻量信息。

根据运行环境选择接入方式：

- 同一小程序应用：内部路由跳转。
- H5 主产品：跳转到学习平台 URL。
- 微信小程序与独立 Web：按平台域名和 WebView 规则接入。
- 未来独立小程序：再评估平台间跳转。

验收标准：

- 学习平台内部页面变更不需要修改主产品业务页面。
- 主产品只依赖公开入口，不依赖学习平台内部数据结构。
- 学习平台可以在不启动主产品的情况下独立展示。
- 主产品不会通过 `cloudSync.ts` 或其他基础设施直接读取学习模块内部 storage。

## 5. 技术栈决策

本方案暂不更换主产品技术栈：

- React：保留。
- TypeScript：保留。
- Taro：继续作为主产品和小程序端宿主。
- 微信云开发：MVP 阶段继续使用。
- 学习平台 Web MVP：采用 React + Vite + React Router，独立负责浏览器展示和试用。
- 学习平台核心：使用纯 TypeScript，供 Web 应用和主产品内的 Taro 过渡入口复用。

后续只有在学习平台出现明确需求时，才评估 Next.js、React Router Framework Mode 或其他带服务端能力的方案，例如 SEO、独立账号体系或更复杂的社区能力；不因为 MVP 展示提前引入 SSR。

## 6. 分支与交付边界

当前分支：


`feature/multilingual-learning-platform`

该分支负责：

- 学习模块独立化。
- 独立 Web 展示入口。
- 本地数据版部署。
- 学习平台的数据接口设计。

主分支暂不吸收不完整的独立部署改动。建议按以下检查点提交：

- Checkpoint 1：学习模块边界冻结。
- Checkpoint 2：学习模块去宿主化。
- Checkpoint 3：独立 Web 可以本地启动。
- Checkpoint 4：独立 Web 可以部署并访问。
- Checkpoint 5：主产品可以通过公开入口接入。

每个检查点都需要单独验证，不将“代码完成”“构建成功”“部署成功”和“真实用户访问成功”混为一谈。

## 7. 完成定义

当以下条件全部满足时，认为该模块完成第一版独立化：

- 学习平台拥有独立应用入口。
- 学习平台拥有独立构建命令。
- 独立 Web 构建使用 Vite 的 `build.outDir=dist-learning`，不会覆盖主产品 Taro 的 `dist`。
- 学习平台拥有独立部署产物和可访问地址。
- 浏览器可以直接展示课程和学习流程。
- 学习进度在展示版中可以本地保存。
- 主产品可以通过路由或 URL 接入。
- 主产品不直接读取学习平台内部课程、进度和成就实现。
- 学习模块边界检查能够阻止或发现宿主深度导入。
- 学习平台的本地数据适配器和未来远程数据适配器边界清晰。
- 有独立 README、部署说明和验收记录。

## 8. 当前不做的事情

为了保持范围聚焦，第一版独立化暂不做：

- 重写主产品主体框架。
- 立即迁移到 Next.js、Vue 或原生 App。
- 立即拆成多个 Git 仓库。
- 一开始就实现完整社区后台。
- 将现有推荐路径规则引擎删除或改造成复杂算法；现有规则引擎保持现状，SM-2 等复杂间隔重复算法后置。
- 一开始就接入支付和商业化能力。
- 为了独立部署而重构晨报、日历、购物和热点模块。

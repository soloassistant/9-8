> **不要**再按下面这段的"未闭环"理解现状；下面保留的是当时的决策过程与取舍理由。

- **已做**：`src/index.html` 的 SDK 标签加 `defer`。产物实测两个脚本都是 `defer`
  （`<script defer src="…workbuddy-cloud-sdk@dev/lib/index.global.js">` → `<script defer src="./js/app.96005064.js">`）。
  defer 按**文档序**执行 → SDK 仍在 app 之前定义全局 `WorkBuddyCloud`，顺序不变
  （页内内联脚本只是 rem 根字号缩放，实测不依赖该全局）。好处：CDN 慢/不可达时**不再阻塞首屏**。
- **没做的（为什么不）**：本机**连不上 `cdn.jsdelivr.net`**（`curl` http=000、WebFetch 也是 fetch failed），
  所以**无法验证"固定到某个版本"后那份产物能否加载**。按"不做未经验证的改动"原则，不落地。
  另外固定版本 + SRI 会把"CDN 抖动"从**友好报错**升级成**整站登不进去**（hash 不匹配即拒执行），是产品权衡。
- **可查事实**（`data.jsdelivr.com` 同日实测）：tag `dev` = `0.1.3-dev.c090db7.202610050023`，`latest` = `0.1.3`。
- **三条待你选**：① 固定到该 dev 版本并加 SRI；② 自托管进 `vendor/` 白名单（要遵守那里的 PROVENANCE 规矩）；

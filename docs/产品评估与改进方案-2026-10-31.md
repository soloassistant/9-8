# 产品评估与改进方案（2026-10-31）

> 依据：PRD v2.0 全文、docs/ 三份竞品文档（10-08 / 10-09 / 10-25）、需求与改进全景（09-15）、
> 晨报领域调研与合规动态（10-21）、AGENTS.md / MEMORY.md / COORDINATION.md 全部现场事实、
> 2026-10-31 对线上站的五项检查与全量门禁（47/47）。结论只写「证据在哪、差在哪、做不做」。

## 一、总判断

**功能广度不缺，缺的是触达闭环、数据入口、商业化通路三条「深度」。**

- 12 页 8 模块（晨报/收件箱/热点/日历/学习/运动/省钱/记账/交易/设置/我的/搜索），
  覆盖面在 46 个竞品样本（归档 morning-brief-competitive-gap-2026-09-24）里属于最宽的一档。
- 但产品定位是「**每天早上**把散落的信息整理成一份晨报」——而当前**晨报不会主动到用户面前**：
  weapp 订阅消息缺模板 ID（卡主体资质），H5 无推送通道。北极星指标「次晨打开率」
  在物理上无法成立。这是与 Gemini Daily Brief（2026-09 起免费并接入 Gmail/Calendar）、
  Ambient、以及泛滥的 WhatsApp/邮件 DIY 投递方案之间**最大的差距**。
- 数据入口只有转发/粘贴/截图（微信平台禁止读聊天记录，转发是唯一合规通道——PRD 决策留痕），
  入口窄是**平台约束**，不是产品过错；但「接入已有日历/邮箱」这条路在 H5 端技术上可行，未排期。
- 商业化两条腿都被资质卡：weapp 支付缺商户号；H5 的订阅态硬编码 false（PRO UI 不可达，
  如实设计但意味着 H5 无收入面）。

## 二、五个维度的决定（调整 or 重写）

| 维度 | 决定 | 依据与剩余工作 |
|---|---|---|
| 视觉 | **调整，不重写** | 晨光 v2 令牌层 + 127 条对比度门禁 + 12 页巡检是已验证资产；重写=全丢。剩余版式债只有一条大的：**≥1024 大屏中列固定 500px、右侧留白**（竞品倒推 C 项），方案：内容列 `max-width` 放宽 + 卡片双列化，纯 CSS |
| UI | **调整** | 侧栏 11 项收口后信息架构健康；小项：二级页冗余「‹ 返回」（桌面有左栏时）、晨报页刷新入口待核实是否已落地 |
| 使用习惯 | **调整** | 语音四件套（松手 200ms 补录/上滑取消/<500ms 误触/TTS 调参）在需求全景标「立即做」但无落地证据，本轮应清；热点流加 5-8% 防茧房探索位 |
| 法律 | **代码侧已到顶，等资质** | v1.8 条文按端披露、注销文案分端、棘轮门禁都在；剩余全是外部阻塞：主体资质（总闸门）、H5 端无内容安全过滤（msgSecCheck 仅小程序）、注销残留三表（I3b，云函数无法部署）。**不写假覆盖**，保持部署就绪度（cloudfunctions 148 条 + cloudflow 359 条断言已保证） |
| 代码 | **不重写** | 47 组门禁 + 359 条行为断言 + 变异验证 + 构建指纹闸，这套质量资产重写丢不起。原列的大债「2.16MiB 无路由分包」**已于 2026-10-29 还清**（`h5.router.lazyload: true`，实测 42 chunks、入口 628KB）——本评估的旧版表述作废；剩余观察项：入口 vendor 构成、投递侧无 gzip（平台侧） |

## 三、功能欠缺清单与加入方案

### P0（零外部依赖：纯前端 + 现有 H5 数据面）
1. **全量数据导出/导入**——现在只有记账 CSV（b4b5e82）。日程/待办/收藏/学习/习惯/记忆都是用户资产，
   设置里没有「我的数据」。导出 JSON + 导入校验，同时天然兜底换设备（SYNC_KEYS 已补 16 键但仍有豁免键）。
2. **资讯源自管理**——41 源写死在源清单，前端无开关/排序。Feedly/Digest 类产品这是标配；
   也是「防茧房」的前置（用户自己留的源，信任度高）。工作量：偏好存储 + 过滤管线一处收口。
3. **话题聚类**（Particle 模式）——同事件多源聚合成一张话题卡。跨源合并（alsoFrom）已有，
   聚类缺；`static-server.js` 的四通道近重复可直接复用，不要另写一套（口径分叉已三次教训）。
4. **摘要分档**（要点/ELI5/多视角）——数据已有（content + summary），补提示词分档与切换 UI。
5. **防茧房探索位**——推荐管线掺 5-8% 非偏好内容（需求全景「中期」项，改一处权重）。
6. **语音细节四件套**——同上表，全在 weapp 端，零资质依赖。
7. **降价提醒**——购物清单加心理价位，到期/降价本地比对提醒（零 API 成本，慢慢买模式的最小替身）。
8. **学习复习算法 FSRS + streak 冻结卡**——Duolingo/Anki 已验证的留存做法，需求全景已立项未做。

### P1（一次云函数部署全解锁 → 主体资质到位即触发）
9. **订阅消息晨报推送**（PRD F04，北极星指标的前置）+ weapp 端 extract 三类提取。
10. **H5 Web Push**（PWA + Push API）——SW 曾试装被撤回（验证不过关），先补验证环境再上；
    这是 H5 唯一可能的触达通道，值得作为独立小立项。
11. **「我的数据」设置组**（P0-1 的 H5 端云端部分：按 owner 删/导出的云函数，顺带清偿 I3b）。

### P2（明确延后，理由已在 PRD 留痕）
12. 邮箱 IMAP 接入实验、引用级溯源（LLM 提示词工程单独立项）、音频晨报章节化（F20，依赖 TTS 通道）、
    海外版（学习模块的多语种底子已埋）。

## 七、订阅价值主张：人家为什么订阅，我们还差什么，能加哪些相关性服务

### 7.1 被验证的六种付费动机（带例证）

| 动机 | 例证 | 我们现状 |
|---|---|---|
| ① 时间账算得清 | Ambient「省一小时/晨」；付费用户为自己看得见的节省买单 | 晨报确实省时间，但**从未量化给用户看**（需求全景的「价值可视化月报」挂在中期未做） |
| ② 资产锁定 | flomo/Readwise：笔记与高亮越存越多，**续费=保护资产** | 我们的数据散在各模块，无导出无备份感，「换设备失忆」反而是负资产 |
| ③ 定版仪式感/信息卫生 | Kagi News：无广告、一天一份读完即完 | 部分具备（已读完横幅），无「版面」概念、无存档 |
| ④ 时效信息差 | 同花顺盘前早报、行业简报：情报直接换钱 | 无关键词追踪（PRD 挂账项），情报是泛化热点 |
| ⑤ 投递通道本身值钱 | Readless 时刻表投递；Gemini 免费化后付费点移向「更深整合」 | ❌ 零投递（卡资质） |
| ⑥ AI 用量天然按量 | 各 AI 助手额度制 | ✅ 唯一已占的一条（语音/情报额度） |

**我们的核心问题（代码自诊断，`language.ts:232`）**：卖点「没有一项可验证」——
免费层已含核心价值（文字晨报+AI 提取+日程全免费），付费点却是「更多量」
（语音 20→∞、收藏 50→∞、情报 3→5 条）。量级差异造不成损失厌恶：用户没有
「不订阅就在失去什么」的感觉。对照六动机：我们只占半个⑥、半个①。

### 7.3 订阅话术修法（直接回应「没有一项可验证」）

1. 每条 PRO 卖点旁边放**用户自己的真实数字**（「你本月已用 18/20 条语音」「已收藏 43/50 条」）。
2. 免费版放对比条：「订阅后 语音∞ / 收藏∞ / 情报 AI 提炼+分组 / 周报存档」。
3. 早鸟锁价 + **涨价前 30 天通知**写进文案（需求全景「立即做」项）。
4. 新增服务的档位归属建议：A/B/C 免费给基础版（周报简版/存档 7 天/1 条 iCal），
   PRO 给完整版（月报+年度/无限存档/多日历）——先免费造习惯，再为「更深」付费。

### 7.4 一句话结论

> 别人订阅的是「**看得见的节省 + 离不开的资产**」；我们现在是「核心全免费 + 付费买量」。
> 修法 = 把核心继续免费钩住获客，把 **周报/存档/备份/追踪** 这四件「越用越值钱」的东西卖成 PRO，
> 并让每一个卖点旁边都站着用户自己的数字。以上 A-F 全部零资质依赖，可在资质到位前做完备弹，
> 部署/支付解锁当天即上架。

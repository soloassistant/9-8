# 「私人晨报助理」代码总结

> 对应源码：仓库 `soloassistant/9-8` main 分支 ｜ 124 个源文件 ｜ 生成于 2026-09-18
> 用途：全文源码见《项目源码整合.md》（560KB），本文档是其架构级总结——每个模块做什么、核心逻辑、数据怎么流。

---

## 一、项目一句话

把微信里散落的会议/机票/待办/链接/截图丢进收件箱，AI 提取日程待办并做冲突检测，每天早上聚成一份**可对话改期**的晨报。北极星 = 次晨打开率。

## 二、双端架构总览

```
┌─ H5 端（本地/线上）────────────────────────────────────┐
│ Taro React SPA (hash 路由)                              │
│   │                                                     │
│   ├─ 数据层 src/services/cloud.ts（环境分流）            │
│   │    ├─ H5: /api/hotspot → static-server 真实 RSS     │
│   │    │    /api/briefing → Open-Meteo 天气              │
│   │    │    chat/extract → localhost:8138 llm-proxy      │
│   │    │    （8138 不可达 → src/data/* 规则 mock 降级）   │
│   │    └─ 小程序: Taro.cloud.callFunction → 12 个云函数   │
│   │         （返回协议兼容裸体/{code,data} 两种）         │
│   └─ 本地持久化: Taro.setStorage（日程/待办/进度/设置）    │
│       小程序端再经 cloudSync.ts 同步云数据库               │
├─ 线上 Pages（纯静态）─────────────────────────────────┤
│ 同一 dist 部署 GitHub Pages；热点走 api/hotspot.json     │
│ （GitHub Actions 每 30 分钟 fetch-data.js 刷新）          │
│ AI 走规则 mock（静态托管无服务端，key 不能进公开仓库）      │
└─────────────────────────────────────────────────────────┘
```

## 三、前端源码 `src/`（78 文件）

### 入口与全局
| 文件 | 职责 |
|---|---|
| `app.tsx` | 应用入口；挂载 `<Splash/>` 开屏（点击进入，全屏 clamp 自适应） |
| `app.config.ts` | 页面注册（11 页）+ tabBar（**只认 PNG**：assets/tabbar-png） |
| `app.scss` | 全局样式；含白屏修复的全局 CSS 覆盖（H5 路由动画已关 `animation:false`，勿改回） |

### 组件（5 个）
| 组件 | 核心逻辑 |
|---|---|
| `Splash` | 开屏封面：品牌橙渐变+logo 动画，**点击任意处淡出卸载**，rem clamp 适配任意屏宽 |
| `AiAssistant` | 悬浮球：**可拖动**（原生事件+边界钳制+位移阈值区分拖/点），点开对话面板（normal/deep/work 三模式）|
| `VoiceButton` | 按住说话→微信同声传译插件 ASR→文本进对话；插件不可用降级纯录音；防误触（<800ms 取消）|
| `EmptyState` | 空态占位（各页复用） |
| `TagChip` | 标签胶囊（资讯 tag/学习词性复用） |

### 页面（11 个）
| 页面 | 职责与要点 |
|---|---|
| `briefing` 晨报 | 首页。晨报卡（日程+待办+天气+情报 digest）+ F21 自适应排序（busyDay 爆满日日程前置/高优待办点名开场）+ F20 音频播报（tts.ts 分块队列） |
| `inbox` 收件箱 | 三通道输入：粘贴文本/截图上传/语音。AI 提取（extract）→ 事件/待办/收藏卡片预览 → 确认落库。冲突检测（schedule.ts 时间重叠算法）|
| `hotspot`→`library` 热点 | 真实资讯流（12 源交错去重）+ 全网搜索 + F22 👍/👎 反馈（本地+云端同步）+ AI 兴趣筛选 |
| `calendar` 日历 | 月视图；当日数据源 getBriefing；F24 忙闲热力着色 |
| `mine` 我的 | 订阅状态/用量、主题/语言/字号（uiScale）、记忆管理仪表盘、注销入口 |
| `search` 搜索 | 全库搜索（日程/待办/收藏/资讯历史） |
| `shopping` 购物 | 清单+记价+AI 比价（chat 云函数 shopping 意图→通义联网） |
| `learn` 学习 | 多语种平台首页：语种选择+分级课程列表+F22 推荐路径卡（续学>复习>新课>起步） |
| `learnDetail` 课程详情 | 单词记忆互动（翻转卡/四选一）+ 进度写入 learn.ts |
| `learnCommunity` 学习社区 | 成就徽章墙（8 枚数据驱动）+ 打卡墙（发帖/点赞，暂本机）+ 昵称 |
| `history` 历史 | 历史晨报归档 |

### 服务层 `services/`
| 文件 | 核心逻辑 |
|---|---|
| `cloud.ts` | **全项目数据总线**。`callFunction()` 环境分流 + 返回协议归一（有 `code` 才校验，裸体透传）；H5 分支按 API 优先真实源、逐层降级 mock |
| `api.ts` | 各业务 API 封装（getBriefing/extract/confirmItem/feedback/getUsage…），统一走 cloud.ts |
| `cloudSync.ts` | 小程序端用户数据上云（users/plans 集合，30s 节流） |
| `location.ts` | 城市定位（行程城市 → 天气查询） |

### 状态与工具
- `store/`：`user`（登录态/订阅）、`theme`（6 色）、`language`（中英 i18n）、`uiScale`（字号）
- `utils/`：`schedule`（冲突检测）、`adaptive`（F21 排序引擎，与云函数内联版同口径）、`learn`（学习进度/FSRS 前置）、`achievements`（8 徽章规则）、`tts`（Web Speech/微信插件双引擎分块队列）、`weather`（Open-Meteo 直连）、`chatLog`、`date`
- `data/`（15 个 mock）：**全部在用**——断网/降级兜底，不删。`learn.ts` 同时是课程词库（内置数据）
- `styles/`：variables（色板）/theme（主题映射）/compat（白屏修复兼容层）
- `types/`：全量 TS 接口（Briefing/PlanItem/HotspotItem/LearnProgress…）

## 四、云函数 `cloudfunctions/`（12 个，Node.js）

| 函数 | 职责 | 关键点 |
|---|---|---|
| `chat` | AI 对话主链路 | DeepSeek deepseek-chat；提示词输出 `{reply,action}` JSON；action=reschedule/done/query/schedule/batch/shopping；llm.js 封装重试 |
| `extract` | 收件箱提取 | 输出 events/todos/collection/note JSON；截图走智谱 glm-4v-flash（需配 key） |
| `confirmItem` | 提取结果确认落库 | 写云数据库 plans 集合 |
| `getBriefing` | 晨报聚合 | **computeAdaptive 内联实现**（勿 require 前端模块）；`main` 识别 `event.Type==='Timer'` 分流定时推送（订阅消息），`exports.scheduled` 仅兼容旧触发器；attachIntel(openid, tripCity) 第二参数=目的地天气 |
| `webSearch` | 联网检索 | RSS 抓取 + 通义 qwen-plus（enable_search）；热点/搜索/资讯反馈落库 |
| `shopping` | 购物比价 | 意图路由到通义联网 |
| `login` | 登录 | code2Session（**手机号登录待主体认证后接**） |
| `getUsage` | 订阅用量 | 免费额度计数 |
| `getLibrary` | 收藏库 | |
| `updateSettings` | 设置同步 | 主题/语言/昵称 |
| `deleteAccount` | 注销 | 清库（≤3 步合规） |
| `createOrder` | 订单 | **只建 orders 记录，cloudPay 回调未接**（需商户号） |

环境变量（云控制台配置）：`LLM_API_KEY`(DeepSeek 必配) / `LLM_WEB_API_KEY`(通义) / `WEATHER_KEY`(和风可选)。

## 五、工具脚本 `.tools/`（5 个）

| 脚本 | 职责 |
|---|---|
| `static-server.js` | 8137 预览服务：静态 dist + `/api/hotspot`（12 源聚合，四级缓存：内存30min→实时→磁盘stale→前端mock）+ `/api/briefing`（Open-Meteo）+ 用户轻云 + AI 筛选转发 8138；来源健康度冷却（连败2次停30min） |
| `llm-proxy.js` | 8138 DeepSeek 代理：`/`(对话) `/extract`(提取) `/filter`(资讯筛选)；key 只在服务端，不进前端产物 |
| `fetch-data.js` | RSS→JSON，供 GitHub Actions 定时刷 Pages（失败退出不覆盖旧数据） |
| `deploy-gh-pages.cmd` | dist 直接提交 gh-pages 根目录（**禁 delayed expansion**，用 commit-tree+push） |
| `deploy-weapp.js` | miniprogram-ci 一键部署 12 云函数+上传体验版（需 appid+private.key） |

## 六、构建与红线（改代码前必读）

1. **构建命令**：`node ./node_modules/@tarojs/cli/bin/taro build --type h5|weapp`（npm.ps1 被 PowerShell 策略拦截，勿用 npm run）
2. **Taro 4.1.9 坑**：config 加 `env` 字段 → weapp 构建全炸；云环境 ID 用 `defineConstants` 注入 `TARO_APP_CLOUD_ENV`
3. **tabBar 只认 PNG**；白屏修复=关路由动画+compat.scss，勿改回
4. **mock 全在用**（降级链 L1内存→L2实时→L3磁盘→L4mock），断网不白屏
5. **自检脚本**：`node .tools/selfcheck.js`（10 项：首页/热点12源/天气/AI真实回复/构建一致/云函数语法）
6. 密钥永不进代码/仓库；`.env.local` 与云函数环境变量两处配置

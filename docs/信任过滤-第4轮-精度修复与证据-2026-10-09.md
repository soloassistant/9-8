## 1. 为什么还会有第 4 轮

这个模块此前被复核 **3 轮**，每轮都"通过"，却反复返工。根因一句话：

> **三轮全部只验证「攻击能否拦住」(recall)，从来没有测量「正常内容会不会被误杀」(precision)。**

于是每轮修复都在提高 recall 的同时悄悄引入新误杀，而**没有任何断言能发现**。
本轮补上 precision 维度，用**双方都没有枚举过**的字符集做泛化攻击，一轮找出 4 个新缺陷 ——
其中 **2 个是前几轮修复自己引入的回归**。

**结论性教训**：给过滤器/守卫写验收，只给「必拦」清单就是不合格，必须同时给「必放」清单。
没有 precision 证据就不算修好。

## 2. 4 项缺陷与修复

### 缺陷 1（回归·中高）：骨架路径误杀正常英文安全新闻

| | |
|---|---|
| 现象 | `Website hacked, by an unknown group, company says` → 判 `defaced` → **静默丢弃**（3/3 测试命中） |
| 根因 | `NEWS_TRUST_NON_SIGNIFICANT_RE = /[^\p{L}\p{N}]/gu`（L314）把**可见的句子标点也删掉**，`hacked, by` → `hackedby`，与投毒签名**完全同形** |
| 修复 | 改为 `NEWS_TRUST_TRANSPARENT_RE`：只删不可见/格式/控制/组合/空白 + **词内**分隔符（`-_·•`），**句子标点保留作屏障** |

⚠️ 关键细节：`U+2800` 盲文空白属 `So`、`U+3164/U+115F/U+1160/U+FFA0` 属 `Lo`，
**Unicode 类别盖不到，必须显式列出**（我的第一版原型漏了 U+2800，导致 `hacked\u2800by` 漏放）。

已验证 **9/9 必拦仍拦**：`hacked by` / `hacked\u200Bby` / `hacked\u00ADby` / `hacked\u2063by` /
`hacked\u2800by` / `hacked\u00A0by` / `h-a-c-k-e-d by` / `h_a_c_k_e_d by` / 逐字零宽夹心 / 跨字段拆词。

### 缺陷 2（回归·中）：`You are now a <普通名词>` 误杀常见英文句式

| | |
|---|---|
| 现象 | `You are now a Premium subscriber — here is what changes` → 判 `inject`。而 `inject` 在 `NEWS_TRUST_HIGH_CONFIDENCE` 里 → **永不被护栏放回** → 静默丢弃 |
| 根因 | `/\byou\s+are\s+now\s+(?:a\|an\|the)\b/i`。冠词约束当初是为修 `nowhere`/`now able` 加的，但没堵住「冠词 + 普通名词」这个极常见合法句式 |
| 修复 | ① 角色词收紧为 **AI 角色名词表**（assistant/ai/model/chatbot/bot/helper/agent/persona/system）；② **补上「抛弃规则」指令从句规则** |

② 的设计理由值得记录：**人设词无法穷举**（`you are now a pirate` 里的 `pirate` 不在任何角色表内），
所以要靠**指令从句**（`forget/ignore/disregard … rules/instructions/…`）来捕获劫持，
而不是继续堆人设词黑名单。该从句带**负向前瞻**排除 `forget the rules **of** X`
这类「讨论式」标题（`of/for/about/in…` 引出宾语，说明规则本身就是话题，不是在给助手下指令）。

### 缺陷 3（正确性·中）：mojibake 误杀正常外文/科学内容，且**随列表构成而变**

| | |
|---|---|
| 现象 A | 俄语整条 `Российские учёные…` 判 `mojibake` |
| 现象 B | **更糟的不一致**：该条与 2 条中文混排时（丢弃比 1/3 < 80%）被**静默删除**；整列都是外文时（100% > 80%）被护栏 **fail-open 放回**。→「正常外文条目能否存活」取决于**列表里还有什么** |
| 现象 C | 中文科普 `α、β、γ、δ 四种射线有什么区别？一文说清` 被丢（≥4 个希腊字母）——对本产品的科技/科学资讯是**现实可发生**的误杀 |
| 根因 | `NEWS_TRUST_MOJIBAKE_RE = /[\uFFFD\u0400-\u04FF\u0370-\u03FF]/g` + 计数 `>3` —— 把「正常外文」与「编码损坏」混为一谈 |
| 修复 | mojibake 收窄为**只看 U+FFFD**（编码损坏的真信号）；同形字改由**混拼词**规则负责 |

**混拼词规则**（新增 `findMixedScriptToken`）：一个**词内部**同时出现拉丁字母与「非拉丁且非 CJK」
的字母 → `confusable`。正常多语言文本总是「整词同一文字系统」（`Российские` / `Η` / `AI`），
只有 `h<西里尔а>cked` 这种跨文字系统拼同一个词才是同形字走私。
**CJK 必须排除**，否则 `AI 技术` 这类大量存在的合法中英混排会被误杀。

### 缺陷 4（注释错误 + 无界绕过）

原注释写道「同形文字**洪水**仍会被 mojibake 规则拦下（> NEWS_TRUST_MOJIBAKE_MAX）」—— **实测为假**：

| 同形字来源 | 修复前 | 修复后 |
|---|---|---|
| 西里尔 `а` ×1 / ×2 | ❌ 漏放 | ✅ `confusable` |
| 西里尔 ×4（洪水） | ✅ mojibake | ✅ `confusable` |
| 希腊 `ο` ×1 | ❌ 漏放 | ✅ `confusable` |
| 切罗基 `Ꭺ` ×1 / ×3 | ❌ 漏放 | ✅ `confusable` |
| 亚美尼亚 `ո` / 格鲁吉亚 `ა` / 科普特 `ⲟ` | ❌ 漏放 | ✅ `confusable` |
| **拉丁 IPA `ɑ` U+0251 / `ɡ` U+0261** | ❌ 漏放 | ❌ **仍漏放（见残余）** |

修复前 mojibake 只覆盖 `[\uFFFD \u0400-\u04FF \u0370-\u03FF]`，**非西里尔/希腊文字系统任意数量全漏**。
注释已改正。

## 3. 明确不做的残余（**勿当已覆盖**）

1. **拉丁系内部的同形字**（IPA `ɑ` U+0251 / `ɡ` U+0261 冒充 a/g）：它们**本身就是**
   `\p{Script=Latin}`，**任何基于文字系统的规则都不可能捕获**，需 confusables 映射表。本轮不做。
2. **攻击者可用句子标点规避骨架签名**：既然 `hacked, by` 现在按正常英文放行，
   那么投毒者写 `hacked, by X` 也能绕过 defaced 检测。这是缺陷 1 的**必然对称面**，
   取舍是「不误杀正常标题」优先。已文档化。
3. 云函数**未部署**；线上仍是旧 bundle `app.2fedd178.js`。

### ⚠️ 关于真实语料的诚实说明

`hotspot-sample.json`（262 条真实条目）上，**修复前后都是零误杀** ——
也就是说**该语料无法区分新旧行为**（它不含本轮针对的内容形态：英文安全新闻、俄语条目、
`You are now a…` 标题、同形字攻击）。

所以：**本轮 precision 修复的证据来自单测，不是来自真实语料。**
不要把这个结果说成「已在真实数据上验证」。它只证明了**没有把现有真实数据搞坏**。

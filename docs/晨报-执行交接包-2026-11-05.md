## 四、发布流程（每次照此，勿简化）

```bash
# 1) 探场：别在别人的 dist 上构建
git log --oneline -3 && git status --short

# 2) worktree 独立构建（不碰主仓 dist）
git worktree add /d/Agent/pub-<tag> HEAD
# node_modules 用 junction：New-Item -ItemType Junction -Path ... -Target D:\Agent\晨报\node_modules

# 3) 构建 + 数据 + 资源
node node_modules/@tarojs/cli/bin/taro build --type h5
node .tools/fetch-data.js --out dist/api/hotspot.json
node .tools/copy-assets.js dist

# 4) 同步发布目录（必须真实目录副本，不能 junction）
robocopy D:\Agent\pub-<tag>\dist D:\Agent\dist /MIR

# 5) 预检 16 项 → 发布 → 发布后 12 项
node .tools/verify-deploy-fresh.mjs --publish
#   → 经 workbuddy_sites_deploy 发布
node .tools/verify-publish-live.mjs

# 6) 摘 junction（(Get-Item ... -Force).Delete()，绝不 rm -r）+ 移除 worktree
```

**判据红线**：
- `verify-publish-live` 全过只证明「线上 == 本地 dist」，**不证明「线上 == 当前 HEAD」**。
  两者可能不一致（历史上出现过落后 11 个提交），所以发布前必须单独比对 HEAD 与 `build-stamp.head`。
- 发布目录路径即 app 身份。`D:\Agent\dist` 消失后重发布 = 新 app + 换域名 → `CLOUD_ENDPOINT` 与 Origin 不匹配 → 必登录失败。
